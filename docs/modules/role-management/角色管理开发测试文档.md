# 系统管理 角色管理开发测试文档

角色管理维护共享角色定义、菜单权限和药企内的用户角色关系。开发重点是正确查询角色成员、限制授权范围，并保证批量增删授权不会产生半成功状态。

本文件供需求评审、开发实施和测试验收使用。请先确认第 4 节的开发任务及第 7 节的业务决策，再按用例执行验收。当前代码存在对应模块，本次补充可实施的开发内容，不将代码存在等同于功能已验收。

## 2 当前实现与数据约束

当前角色页面已有查询、新增、编辑、状态、删除、菜单树授权和分配用户抽屉。sys_role 与 sys_role_menu 是共享配置，sys_user_role 按药企隔离。非平台超级管理员的共享配置写入会被 TenantWebConfig 拦截；/authUser/ 成员关系接口属于例外，仍须检查操作权限及目标用户归属。

保留角色 ID=1 和 superadmin 标识受保护；已分配用户的角色不允许直接停用或删除。角色更新和成员关系变更存在注销在线会话逻辑。静态核对发现 selectAllocatedList 未使用传入 roleId 筛选，可能使其他角色用户被误认为已分配成员。成员抽屉先取消再新增，两个请求之间没有统一事务。

### 2 1 主要字段

| 字段 | 当前约束与开发关注点 |
| --- | --- |
| roleId / roleName | 角色 ID 为主键；角色名必填且最多 30 字符，应用层检查名称唯一。 |

| userIds / roleId | 成员授权参数；关系表按用户、角色组合约束，批量操作需先校验完整集合。 |
| delFlag / remark | 角色采用逻辑删除；删除同时清理角色菜单关系，先检查是否分配用户。 |

## 4 开发内容与实施顺序

以下任务均为计划开发、待评审，尚未修改业务代码。P0 优先处理权限、数据正确性和事务问题；P1 补齐交互与异常。按任务顺序实施，接口或数据库方案评审通过后再编码。路径别名见第 8 节。

### DEV ROL 001 修复成员查询与分页契约

优先级 P0；关联 REQ-ROL-006、REQ-ROL-010。

现状依据：B/java/org/dromara/system/service/impl/SysUserServiceImpl.java 的 selectAllocatedList 未用 roleId；B/resources/mapper/system/SysUserMapper.xml 的对应查询仅 left join 后套条件。PageQuery 未传 pageSize 默认 Integer.MAX_VALUE。

开发方案：在已分配查询中加入目标角色的明确条件，并校验 roleId；复杂关联放 XML。保持已分配与未分配语义互斥及药企过滤。成员抽屉显式分页；全量选中状态可采用仅 ID 的受控查询或服务端差量接口，具体新接口在评审后定义，不继续无上限拉全量用户。

完成标准：R1、R2 及无角色用户交叉数据下已分配集合精确；大数据分页和空角色 ID 均正确。TC-ROL-011、012、019、020 覆盖。

### DEV ROL 002 统一授权服务及事务

优先级 P0；关联 REQ-ROL-002、REQ-ROL-007、REQ-ROL-008。

现状依据：SysRoleServiceImpl 的成员接口已有用户归属与禁止自改校验；insertAuthUsers 未见完整目标角色存在、状态及保留角色校验。role-auth-user-drawer.vue 顺序发送 cancelAll、selectAll。

开发方案：服务层统一校验角色存在、启用、非保留且在操作者可委派范围内；所有用户先校验归属和存在性，再写入。建议新增一次提交增删差量的原子服务接口，名称和契约评审后定；在单事务内完成取消与新增，前端改为一次请求，空差量不写入。

完成标准：混入 B 用户、当前用户、无效角色或中途注入失败时全部回滚；正确差量一次完成。TC-ROL-003、004、013 至 016 覆盖。

### DEV ROL 003 补齐角色与菜单集合校验

优先级 P0；关联 REQ-ROL-003、REQ-ROL-004、REQ-ROL-005。

现状依据：SysRoleBo 的 menuIds 可为 null，SysRoleServiceImpl.insertRoleMenu 直接遍历；前端 MenuTree 包含虚拟根 0，并可返回半选父节点。后端缺少集合存在性检查。

开发方案：按新增、编辑、状态分组校验 ID、状态、名称及标识；menuIds 明确 null 与空的含义，建议 null 拒绝、空集合表示无菜单。提交前排除根 0、去重，服务端再查全部菜单有效性；共享角色授权保持父子路径完整。保留角色保护统一复用，未知角色返回业务错误。

完成标准：无 null 遍历异常、无 0 或悬空关联；清空授权与回显结果一致，保留角色不可变。TC-ROL-005 至 010 覆盖。

### DEV ROL 004 统一权限生效和会话异常处理

优先级 P0；关联 REQ-ROL-009。

现状依据：SysRoleServiceImpl.cleanOnlineUserByRole 按在线令牌搜索受影响用户，成员更新也清理会话。需要验证筛选准确性、事务后执行及大在线量开销。

开发方案：与用户模块统一权限变更入口，数据库提交后仅处理受影响用户，避免提前注销后事务回滚。清理失败可追踪、可重试；性能不足时评审用户到会话索引，不先增加新基础设施。停用已分配角色仍按当前规则拒绝。

完成标准：角色授权收回后旧令牌不能继续用旧权限；无关用户会话有效。异常不报告虚假的全成功，TC-ROL-017、018 覆盖。

### DEV ROL 005 完善成员勾选和抽屉容错

优先级 P1；关联 REQ-ROL-010、REQ-ROL-011。

现状依据：role-auth-user-drawer.vue 的候选用户使用 /system/user/list，额外依赖 user:list；角色编辑菜单读取失败时提前 return，部分 loading 未释放。

开发方案：以原始成员集合加 add/remove 差量保存跨页选择，筛选不等于取消隐藏成员；重载与关闭有明确未保存提示。设置合理页大小与总量提示。为角色列表、菜单树和成员抽屉标明权限缺失，try/finally 释放 loading，保存时禁用重复提交。

完成标准：翻页、查询、失败重试不误撤销未显示用户；树请求失败后可再次打开，TC-ROL-019 至 022 覆盖。

### DEV ROL 006 补齐并发审计及导出边界

优先级 P1；关联 REQ-ROL-003、REQ-ROL-012。

现状依据：名称及标识主要依赖应用层唯一检查；普通用户的角色导出 POST 会被共享配置写拦截拒绝。现有授权日志入口存在，但组合操作需一致结果。

开发方案：唯一性并发校验与数据库约束按存量检查后评审；关系新增去重或安全幂等，编辑角色考虑更新时间/版本冲突提示。原子授权日志记录目标角色、增删数量及结果，避免记录无关个人信息。导出是否允许普通管理员需业务决定，再决定精确放行该接口，禁止扩大所有非 GET 例外。

完成标准：并发同名、重复关系与过期编辑有可解释结果；导出遵守确认策略，TC-ROL-023、024 覆盖。

### 4 7 数据变更与联调要求

先沿用现有表和逻辑删除约定，不直接改初始化 SQL 充当已部署环境升级。若任务确需新增索引或字段，在 script/sql/update 下新增经评审的增量迁移；先检查存量异常，给出兼容及回滚方案。简单查询使用 MyBatis-Plus，复杂多表查询按项目约定放 Mapper XML。

每次改动同步前端 API 类型、参数绑定、服务端校验与测试。涉及数据库关系的写入在同一事务中完成；会话失效和缓存处理属于事务外效果，应在提交后执行并记录失败，不以数据库回滚假装撤销已失效的会话。

联调顺序：先补用户身份与药企归属校验，再处理角色及用户关系，最后联调菜单授权、路由与按钮权限。用户管理中的角色选择可先使用隔离环境预置角色，最终必须执行三模块联动验收。
