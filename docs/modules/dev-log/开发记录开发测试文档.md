## 1 模块目标与范围

开发记录用于登记系统功能新增、缺陷修复和变更调整，保存标题、分类、版本、详细内容、开发人员、记录日期及一份关联记录文档。当前支持分页查询、新增、修改和附件下载；页面无删除、批量选择、导出或导入入口，控制器未提供删除接口。

分类是业务类型，不是审核状态。feature 对应功能新增，fix 对应缺陷修复，change 对应变更调整；页面以中性标签展示。version 为可选文字，不代表 Git 提交、发布状态或附件版本。developer 是手工录入的文字，不等于真实登录操作者。

本模块与 3Q 文档管理、3Q 验证记录同处合规管理目录，但使用独立记录表和附件配置。本文仅覆盖开发记录，不把关联菜单中的上传、验证结果或文档分类能力算入本模块。

本版未打开在线页面，页面描述来自 Vue 源码；未核实部署提交、实际角色授权、配置覆盖、目录挂载和历史数据。代码存在不等于已部署，更不等于业务验收通过。

## 2 当前行为与历史资料差异

历史设计采用 uuid 主键、PG 时间类型、全量列表、统一保存和删除接口；当前实现采用 Java / Spring Boot、MyBatis-Plus、MySQL bigint 自增主键及 Vue / Naive UI，查询为服务端分页，新增和修改分别使用 POST、PUT，新增了 version、fileName 及上传下载接口。

历史权限为 read:ComplianceRecord 和 manage:ComplianceRecord，角色矩阵列出湿实验、生信、解读与运营管理员。当前实际接口使用 compliance:devLog:list、query、add、edit 四个权限点。菜单 SQL 为角色 1 插入授权，不能据此认定历史四个角色已经创建或获得授权；部署数据库权限需实际核验。

仓库数据库规范及部分注释称 dev_log 为 append-only、不可删改；实际控制器提供 PUT，服务调用 updateById 修改原行，附件按同名覆盖。准确描述应为“当前不提供删除，允许原行编辑，附件可替换”。未发现本模块独立的历史修订表、旧附件版本保存或内容不可篡改机制，本文不将其宣传为不可篡改证据。

旧设计按 logDate、createdAt 倒序；当前服务实际按 logDate、id 倒序。列表展示创建时间 createTime，没有记录日期 logDate 列，记录日期仅在维护抽屉录入。测试应区分两个日期，而非用列表创建时间判断排序是否正确。

## 3 字段与持久化定义

实体 DevLog 对应 dev_log，继承 BaseEntity。七个业务字段在前端表单、Bo、实体和 Vo 中对应；分页返回另含 id 与 createTime。表中没有 del_flag，未配置逻辑删除字段。

| 字段或约束 | 当前实现 |
| --- | --- |
| id | bigint 自增主键；前端新增模型不传 id；修改服务要求非空且记录存在 |
| title | varchar(200)，必填；Bo 同时约束 NotBlank 与 Size，显式适用于 AddGroup、EditGroup |
| category | varchar(20)，必填；Bo Pattern 只允许 feature、fix、change，前端 NSelect 单选且新增默认 feature |
| version | varchar(50)，可空，只有长度约束；无唯一性或版本格式校验 |
| content | text，可空，前端多行文本；Bo 未声明内容长度上限，实际存储容量仍受数据库和请求限制 |
| file_name / fileName | varchar(255)，可空；存文件名而非完整目录；Bo 仅校验最大长度，保存服务未校验文件存在、上传来源或归属 |
| developer | varchar(80)，可空，普通文本；未绑定用户表或登录身份 |
| log_date / logDate | SQL date，可空；Bo 使用 java.util.Date；前端提交 yyyy-MM-dd，Vo 明确按 yyyy-MM-dd 输出，输入解析仍需联调验证 |
| 公共字段 | create_by、create_time、update_by、update_time；由现有底座维护，Vo 展示 createTime，不能将这些列等同于完整修改历史 |
| tenant_id | varchar(20)，非空、默认 000000；普通业务 SQL 由租户拦截器附加归属条件，平台管理员可绕过该过滤 |
| 索引 | 主键 id；idx_tenant_id；idx_dev_log_date(tenant_id, log_date)；idx_dev_log_category(tenant_id, category) |
| 表级约束 | utf8mb4_general_ci；没有标题、版本或文件名唯一约束，没有分类数据库 CHECK 定义，没有删除标志 |

Bo 已显式声明新增、编辑校验组，不存在样本信息文档中同类校验组遗漏的直接证据。分类查询不经过新增、编辑分组校验，只按非空字符串精确过滤；不能把写入枚举校验推断为查询时也一定拒绝未知分类。

全局 common-mybatis.yml 配置 updateStrategy: NOT_NULL，实体各业务字段未单独声明清空策略。更新传 null 时按该基线可能不写入该列；尤其前端移除附件只把 fileName 设为 null，保存后是否仍保留原关联需重点核验。空串与 null 应分别测试，不能视为同一操作。

## 4 接口与权限

以下为已存在的后端路径，不包含代理前缀。普通响应使用 R，分页使用 TableDataInfo，下载直接返回文件流。错误由项目统一封装，未在本次运行中确认 HTTP 状态码。

| 方法与路径 | 权限及请求响应 |
| --- | --- |
| GET /compliance/devLog/list | compliance:devLog:list；title、category、developer 与 pageNum、pageSize；返回 rows、total 的分页结构 |
| GET /compliance/devLog/{id} | compliance:devLog:query；主键非空；返回开发记录详情，不存在时抛业务异常 |
| POST /compliance/devLog | compliance:devLog:add；JSON 请求体、AddGroup 校验；操作日志 INSERT、RepeatSubmit；返回操作结果 |
| PUT /compliance/devLog | compliance:devLog:edit；JSON 请求体、EditGroup 校验；要求 id；操作日志 UPDATE、RepeatSubmit |
| POST /compliance/devLog/upload | compliance:devLog:add；multipart/form-data 的 file；返回 data.fileName；操作日志 INSERT，未配置本接口 RepeatSubmit |
| GET /compliance/devLog/download/{id} | compliance:devLog:query；先按 id 查询记录，再根据其 fileName 返回 application/octet-stream 附件流 |

上传复用 add，下载复用 query，没有独立 upload、download 权限点。只有 edit 的用户可以保存文字修改，但上传会被 add 权限拦截；列表文件名按钮未按 query 单独隐藏，因此只有 list 的用户可能看见下载按钮，点击后仍受后端 query 控制。

list 返回记录内容及文件名，query 单独控制详情和下载。不能将缺少 query 视作内容完全不可见。当前前端编辑从列表行复制数据，打开抽屉时未调用详情接口，编辑因此不以 query 为必需前置。

## 5 开发实现说明

以下八节描述已存在的代码职责和处理流程，不是新增开发任务。

### DEV DLOG 001 页面与查询实现

关联 REQ-DLOG-001、002。index.vue 复用 useNaivePaginatedTable、useTableOperate，默认每页 10 条。搜索模块提供标题、分类、开发人员三项；标题与开发人员用 LIKE，分类用等值条件，组合为 AND。服务按 logDate 倒序、再按 id 倒序，日期为空时的显示顺序需在目标数据库核验。

列表列为序号、分类、记录标题、版本、内容、记录文档、开发人员、创建时间及操作。序号计算为“(页码−1)×页大小＋当前行序号”，不是记录 id；内容使用省略提示，空的版本、内容、开发人员以空值判断显示短横线。列设置、刷新及窄屏分页沿用现有组件。

### DEV DLOG 002 表单及校验实现

关联 REQ-DLOG-003、004、005。抽屉宽度 600，新增初始化七个字段，分类默认 feature，其余文字或日期为空。前端显式配置标题、分类必填；后端控制器触发 Bo 分组约束，限制标题 200、版本 50、开发人员 80、文件名 255 字符及分类枚举。

编辑复制当前列表行到新模型，上传列表根据保存的文件名回显为 finished。提交失败保留抽屉及输入，成功后关闭并刷新；保存期间取消按钮禁用、确认按钮 loading。关闭图标仍为 closable，未见保存状态联动的遮罩、Esc 和关闭图标限制；实际交互需验证。

### DEV DLOG 003 数据保存与无删除实现

关联 REQ-DLOG-005、006、013。insertByBo、updateByBo 都有数据库事务，使用 Mapstruct 转换和 BaseMapperPlus 写入，以影响行数是否大于 0 判断结果。修改先检查 id，再 queryById 确认存在。不存在记录抛出“开发记录不存在”业务异常。

DevLogMapper.xml 没有自定义 SQL。当前无删除方法、无 DELETE 映射及 remove 菜单权限；新增与修改并没有标题查重或版本冲突检查。RepeatSubmit 是请求防重复机制，不等于持久业务唯一性或多人编辑冲突检测。数据库事务不覆盖独立上传接口已经写入的文件。

### DEV DLOG 004 记录权限与药企上下文

关联 REQ-DLOG-007、008。Controller 的 SaCheckPermission 对六个接口逐一鉴权；页面通过 add、edit 控制对应入口。dev_log 不在共享表白名单，普通用户的查询、新增和修改依赖现有租户插件；当前文件目录没有附带同等药企维度。

平台管理员可绕过租户过滤。表单和 DevLogBo 没有业务目标药企选择字段，跨药企创建时实际归属需对照运行环境验证，不能宣称已支持指定药企创建。开发人员文本由维护者填写，实际操作者需查看公共维护字段和操作日志。

### DEV DLOG 005 上传与文件命名实现

关联 REQ-DLOG-009、010、011。前端 NUpload 选择文件后走模块上传接口，最多一个列表项，未设置 accept 类型白名单；上传完成回填 response.data.fileName。前端声明 file-size 为 20，但没有专用上传前大小校验函数，不能仅依据该属性确认组件限制生效。

服务先拒绝空文件和缺失文件名，把文件名中的反斜线换为斜线，取最后一段并 trim；空名、单点和双点被拒绝。随后创建配置目录并直接写入同名目标，源码注释明确采用重名替换。服务未显式检查扩展名、内容类型、大小或文件名长度；文件系统错误通过业务异常返回，异常消息可能包含底层路径信息。

配置键为 compliance.dev-log.upload-dir，基础 application.yml 指向服务器固定目录；multipart 基础配置为单文件 10MB、整请求 20MB。最终限制可能受环境覆盖或网关影响，本文仅记录仓库配置，测试须记录实际部署值。上传即写文件，不等待表单确认。

### DEV DLOG 006 附件关联与下载实现

关联 REQ-DLOG-010、011、012。记录只保存 fileName。下载先执行 queryById，再取文件名；无附件则报错，使用目录 resolve 加 normalize 构造路径，检查目标仍位于配置目录内且是普通文件，然后设置下载响应头并写文件流。前端复用 useDownload 的 GET 下载器携带现有身份信息。

目录由全局配置决定，没有按药企、记录 id 或附件版本分目录。同目录同名附件只有一个目标位置；多条记录引用同名时读取同一目标文件。因此另一条记录甚至另一药企的同名上传可能影响已有下载内容。记录数据库隔离不能证明文件内容隔离。

新增、修改服务没有把 fileName 与上传者、药企或记录绑定核验，直接提交已有文件名也会进入保存流程。下载路径检查可以阻止词法上的目录越界，但并未证明目录内文件归属合法。这些是待运行复现的边界，不写成已通过的隔离要求。

### DEV DLOG 007 上传与保存的独立状态

关联 REQ-DLOG-011、013。前端移除仅清空表单 fileName，不删除服务器文件；上传后取消抽屉也没有撤销上传。若上传覆盖的是其他已保存记录引用的文件，取消本次保存不会恢复之前内容。

表单 saving 与上传任务没有统一忙碌状态，未见阻止上传过程中点击确认的判断。上传响应在何时回填、提交捕获到哪个 fileName、失败重试及晚到响应对下一次打开抽屉的影响，均须运行核验。上传回调直接 JSON.parse，非 JSON 响应没有显式保护分支；上传头在组件初始化时取得 token，身份过期后的表现不能凭代码认定。

### DEV DLOG 008 数据部署与证据边界

关联 REQ-DLOG-014。business/compliance.sql 包含建表、合规目录、开发记录菜单和 list/query/add/edit 权限定义；现有数据库使用 update_5.6.2-dev-log-version-file.sql 增加 version 与 file_name，脚本先检查列是否存在，避免重复添加。

迁移文件注释说明现有数据卷不会自动重跑初始化 SQL，实际是否执行仍须核验。配置注释提到持久化卷，但本次未检查服务器挂载，不能据此保证重启后附件可用。附件与数据库分别保存，数据库回滚不撤销已完成的文件覆盖。

新增、修改、上传已有操作日志注解；下载未声明本模块操作日志注解。公共字段与操作日志不能证明旧内容、旧文件或每次修订都可重建。本次未运行 Maven、前端编译、业务测试或迁移脚本；在相关测试目录的文件名检索中未发现 DevLog 专用测试，这不代表已经穷举所有通用测试覆盖。

## 7 测试准备与记录方式

在隔离环境准备药企 A、B，各设普通维护用户，并准备 list-only、list+query、list+edit、list+add 与无权限角色，以及平台管理员。权限组合以实际配置为准，不仅看角色名称。账号凭据通过受控环境提供，不写进文档。

测试记录全部为合成数据，例如“测试功能记录甲”，分类分别 feature、fix、change。准备超过 10 条数据，覆盖相同记录日期、不同创建时间、空日期、长标题及开发人员名称；示例版本 v1.0 只是测试文本。

附件使用无敏感信息的测试文本，内容分别标记 TEST-A、TEST-B，同名样本使用 test-dev-record.txt。覆盖同名、取消、路径边界和并发用例只能使用独立测试目录与可丢弃文件，避免影响真实记录。部署限制用例记录实际单文件、请求和网关上限，再准备边界文件。

每个用例保留构建版本、角色权限、药企、操作时间、请求响应、记录前后值和必要文件摘要。涉及文件覆盖以内容或摘要比对，不能只看文件名。运行结束后的测试数据清理由环境负责人按授权处理；没有业务删除接口不代表可直接清理真实数据库。

全部业务用例状态为“待执行”。基线用例的预期用于核对代码行为；差异核验用例若复现缺口，应记录限制或缺陷，不因为“与代码一致”就计作业务验收通过。未执行和无法验证必须分别记录，不填通过。

## 10 当前限制汇总

1. 注释与行为不同：称不可删改，但允许 PUT 修改原行；无删除不等于不可篡改，未见独立修订历史。
2. 文件目标共用：同名替换，不按药企或记录区分；数据库记录权限与附件内容归属不是同一个检查。
3. 文件关联未验证：保存只接收文件名，未验证该文件由谁上传、属于哪条记录或是否存在。
4. 两阶段独立：上传已写磁盘，保存失败、取消或移除不会撤销；没有数据库与文件的统一事务。
5. 空值与竞争：NOT_NULL 可能使移除关联不落库；上传与保存无明确忙碌联动；编辑未读取最新详情或验证版本。
6. 权限与显示：上传需要 add，只有 edit 不足；文件名下载按钮可见不意味着已有 query；历史角色矩阵并非部署授权证明。
7. 配置与错误：前端声明 20、基础单文件限制 10MB；服务无类型白名单，文件名和 IO 异常需实测，非 JSON 上传返回可能触发解析错误。
8. 数据含义：developer 是文字，version 是文字；列表显示 createTime 而按 logDate 排序；记录没有审批、发布或验证结果状态。

以上仅记录现状及验证边界。本版未提出、批准或实施任何改造方案。
