## 3 页面交互与字段

### 3.1 列表与搜索

页面为搜索卡片加药企列表。搜索条件为药企编号、药企名称和状态；输入框支持 Enter 搜索。搜索和刷新清空勾选并回第一页，重置恢复初始筛选条件。默认每页 10 条，公共分页组件提供 10、15、20、25、30 条选项。

表格列为选择框、药企编号、药企名称、状态、创建时间、备注和操作。名称及备注使用省略与提示。工具栏提供新增、批量删除、刷新和列设置。单条及批量删除都有确认；默认药企可编辑名称和备注，但不可勾选或删除。

状态来自 sys_normal_disable 字典，值 0 表示正常，1 表示停用。页面状态标签由 DictTag 渲染，显示文字和颜色依赖运行环境字典与缓存，须在在线环境核验，不能仅凭页面代码判定实际颜色。

新增、编辑共用 420px 抽屉，最大宽度为视口 90%。编辑直接复制当前行数据初始化，没有请求详情接口。新增默认正常状态；编号和名称在提交前 trim。保存成功关闭抽屉并刷新；新增回第一页，编辑刷新当前页；删除成功清除勾选并刷新当前页。删除末页最后一条后的页码修正需专项验证。

### 3.2 字段定义

| 字段 | 类型与约束 | 页面及服务端行为 |
| --- | --- | --- |
| id | bigint，主键自增；实体 Long | 新增清空传入 id，数据库生成；编辑必需；不在表单中输入 |
| tenantId | varchar(20)，非空，唯一 | 1～20 位 A～Z、a～z、0～9、下划线或短横线；编辑禁用，后端禁止变更 |
| tenantName | varchar(100)，非空 | 必填且非空白；最多 100 字符；当前不校验名称唯一 |
| status | char(1)，非空 | 仅 0 或 1；数据库默认 0，但接口要求显式提供有效值 |
| remark | varchar(500)，可空 | 最多 500 字符；页面多行输入，不主动 trim |
| createBy 与 createTime | bigint 与 datetime | 公共审计字段；列表显示创建时间 |
| updateBy 与 updateTime | bigint 与 datetime | 公共审计字段；实际自动填充和操作人归属需联调验证 |

编号 000000 是默认药企；`__platform__` 为平台日志保留标识，新增接口明确拒绝。000000 的重复新增由唯一性检查拒绝。编号与名称去空格是页面行为，服务端实体未提供同等 trim：直接提交带空格编号会因格式被拒绝；非全空白名称的首尾空格不保证由接口去除。

名称、备注边界用常用汉字或 ASCII 测试，避免表情代理对造成字符计数歧义。更新策略为 NOT_NULL：接口传 remark=null 可能保留旧值，页面清空备注传空字符串可与此不同，需按 TC-TEN-023 实测并确认产品约定。

### 3.3 数据库基线

轻量 sys_tenant 的依据是 update_5.6.2-tenant-version.sql，含唯一索引 uk_sys_tenant_identifier(tenant_id)，无逻辑删除字段。药企目录删除调用 deleteByIds，为物理删除；关联业务表的逻辑删除记录仍会被 COUNT 检测到，可能阻止药企删除。

ry_vue_5.X.sql 中保留了上游完整租户表，不能直接等同于当前轻量模型。rbac-only 脚本先移除上游租户表，再由 tenant-version 脚本建立轻量目录；tenant-version 中 CREATE TABLE IF NOT EXISTS 不会将旧表自动改造成轻量表。既有数据库应核对实际表结构和已执行迁移，不在本次任务重跑初始化或删表脚本。

仓库 Docker 配置使用 MySQL 5.7.26，默认排序规则为 utf8mb4_general_ci；租户建表 SQL 未显式声明 COLLATE。线上实例不一定使用此配置，编号大小写、尾随空格及唯一索引的比较语义必须实查，不据此直接宣布大小写规则已确认。

## 4 接口与权限

### 4.1 接口契约

以下路径为后端业务路径。前端代理前缀、鉴权客户端参数和实际部署地址从环境配置核验，不将页面 URL 当作后端根地址。普通接口返回 R 包装，列表返回 TableDataInfo；成功或失败同时检查业务 code、msg 与实际数据，不能只检查 HTTP 状态。

| 方法与路径 | 输入与结果 | 权限和约束 |
| --- | --- | --- |
| GET /system/tenant/list | tenantId、tenantName、status、pageNum、pageSize；返回 rows、total 等分页信息 | 超级管理员；编号精确、名称模糊、状态等值 |
| GET /system/tenant/options | 无业务参数；返回启用药企列表 | 已登录；按当前身份限制范围；查询选择 id、tenantId、tenantName、status |
| GET /system/tenant/{id} | id 为数据库主键；返回详情 | 超级管理员；不存在则报错；前端编辑暂未使用此接口 |
| POST /system/tenant | JSON：tenantId、tenantName、status、remark | 超级管理员；新增校验；忽略传入主键；记录 INSERT 操作日志 |
| PUT /system/tenant | JSON：id、tenantId、tenantName、status、remark | 超级管理员；字段校验、存在性、编号不可变、默认药企保护 |
| DELETE /system/tenant/{ids} | 一个或多个主键，逗号分隔 | 超级管理员；事务、存在性、默认药企与关联数据检查 |

选项接口只选择四个数据库列，返回类型仍为实体列表；序列化后是否出现其他空字段由全局配置决定。测试重点是未返回未授权药企及敏感内容，不把数据库 select 列数误当成 JSON 必须恰好四个键。

## 5 开发处理流程与注意事项

### 5.1 分层及关键流程

前端 tenant 页面调用 service/api/system/tenant.ts；Controller 处理管理身份、参数校验、响应、操作日志和防重复提交；Service 处理规则，SysTenantMapper 继承 BaseMapperPlus 完成单表操作。

新增流程：页面去空格 → 表单校验 → 设置保存中 → POST → 后端字段校验及身份检查 → 拒绝平台保留编号 → 清空请求主键 → 检查编号唯一 → INSERT → 提示成功并刷新。页面保存中避免连点，关闭按钮、遮罩关闭及 Esc 按保存状态受控；异常后 finally 解除保存中。

编辑流程：复制行数据 → 允许编辑名称、状态、备注 → PUT → 查询原记录 → 核验编号不变及默认药企状态 → UPDATE。当前没有版本字段或乐观锁比较，不承诺并发编辑冲突提示；若业务需要防覆盖，应单独设计。

删除流程：读取当前数据库中除 sys_tenant 外含 tenant_id 的表 → 逐个校验目标存在及非默认药企 → 校验表名仅含字母数字下划线 → 参数绑定查询关联记录数 → 全部通过后批量 DELETE。整个方法有事务，但并发写入关联数据时的竞态保护仍需专项设计和实测，不以事务注解推断所有并发路径安全。

### 5.2 登录与隔离联动

登录服务校验用户所属药企状态；TenantWebConfig 对已登录请求再次校验，退出登录接口放行。停用会使旧会话的后续受校验请求失败，不等于主动销毁所有 Token；恢复后旧 Token 是否继续有效要结合有效期和会话策略验证。

普通用户业务表默认添加 tenant_id 条件，新增归属使用可信上下文。超级管理员或受控忽略上下文可跳过过滤；sys_tenant、菜单、角色、字典、配置等共享表以及指定基因库表在排除集合中，sj_ 前缀表也被排除。不能用“所有表都按药企过滤”作为验收断言。

### 5.3 实现差异与后续建议

当前 Service 用 JdbcTemplate 查询数据库元数据并拼装经校验的表名，尚未按项目复杂 SQL 规范放入 Mapper XML。若整改，应保留动态标识符校验、值参数绑定和批量原子性；不直接将客户端字段拼入 SQL。

当前 Controller 直接使用 SysTenant 作为请求及返回实体，未按新模块规范独立 BO、VO；权限由硬编码超级管理员身份决定。后续涉及该模块时评估拆分请求响应对象、明确字段白名单及统一可读性风格，不为文档交付顺手重构。

删除末页记录后的页码修正、不同管理员并发编辑、同编号并发创建、删除与关联写入竞态均是补充验证点；发现异常后建立缺陷，不在未执行时写成已复现缺陷。
