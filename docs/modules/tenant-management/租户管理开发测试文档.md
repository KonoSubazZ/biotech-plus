## 字段与接口

### 核心字段

存储表为 sys_tenant。状态值“0”表示正常，“1”表示停用。

| 字段 | 约束与含义 | 页面行为 |
| --- | --- | --- |
| id | Long 主键；新增由后端生成；更新必须提供 | 不允许手工编辑 |
| tenantId | 必填，1～20 位字母、数字、下划线或短横线；全表唯一；创建后不可变 | 提交前去除首尾空格；编辑时禁用 |
| tenantName | 必填，最多 100 字；当前未要求名称唯一 | 提交前去除首尾空格 |
| status | 必填，仅允许 0 或 1；页面新增默认 0 | 默认租户状态不可修改 |
| remark | 可选，最多 500 字 | 多行文本 |

保留编号 000000 是默认租户，`__platform__` 是平台专用标识。后者即使满足字符格式，也不能通过新增接口创建。名称重名当前允许；是否调整由业务确认。

### 接口清单

统一前缀为 /system/tenant。管理接口在控制器中检查超级管理员身份；选项接口根据当前登录租户过滤。

| 方法与路径 | 输入和返回 | 关键校验 |
| --- | --- | --- |
| GET /list | tenantId、tenantName、status、pageNum、pageSize；返回 TableDataInfo | 超级管理员；组合筛选 |
| GET /options | 无业务参数；返回 R 包装的租户数组，含 id、tenantId、tenantName、status | 只返回启用租户；按身份限制范围 |
| GET /{id} | 主键；返回 R 包装的租户详情 | 超级管理员；不存在时报错 |
| POST 空路径 | JSON 租户对象；返回 R，无业务数据 | 超级管理员；字段、重复编号、保留编号校验 |
| PUT 空路径 | JSON 租户对象，含 id；返回 R，无业务数据 | 超级管理员；编号不可变；默认租户保护 |
| DELETE /{ids} | 一个或多个主键，多个用逗号分隔；返回 R | 超级管理员；默认租户及关联数据保护 |

接口的错误应结合项目统一响应体判断，不能仅按 HTTP 状态码判断成功。本文不假设未核实的错误码。

## 开发说明与测试准备

### 当前处理流程

列表页调用分页接口；新增和编辑使用侧边抽屉，成功后刷新列表。编辑使用当前行数据初始化，前端目前没有单独请求详情接口。默认租户不可勾选，隐藏删除按钮；本模块页面不提供导出。

后端由 SysTenantController 校验管理身份，再交给 SysTenantServiceImpl 处理字段和业务规则。列表和选项使用 MyBatis-Plus 条件构造器；选项先查询当前身份，再显式增加租户条件，按主键升序返回。

删除操作在事务中完成。当前服务查询数据库元数据，检查除 sys_tenant 外具有 tenant_id 列的表；发现任何关联记录则拒绝删除。批量删除先检查全部租户，再执行删除。依赖应用数据库账号可读取相应元数据和表。

登录流程检查租户状态，已登录用户的后续请求也经过租户校验。共享基础表按项目配置排除租户隔离，业务表按 tenant_id 过滤。不能把“所有表均隔离”作为验收条件。

### 已知实现差异

租户删除的元数据及关联数据检查目前写在 Service 中，使用 JdbcTemplate，尚未符合“复杂 SQL 写入 Mapper XML”的项目规范。本文记录该差异；本次不改业务代码。后续如整改，应保留表名白名单检查和参数绑定，并回归批量原子性。

### 测试环境与数据

| 准备项 | 要求 |
| --- | --- |
| 环境 | 独立测试数据库、缓存及后端；记录前后端提交、数据库版本和执行时间 |
| 身份 | 超级管理员 S；启用租户 A、B 的普通用户 UA、UB；凭证由环境提供，不写入文档 |
| 租户数据 | A、B 启用；C 停用；E 无关联数据；D 有关联用户或业务数据；使用唯一测试编号 |
| 隔离数据 | A、B 各自拥有可识别的用户或业务记录；保留原始记录便于比对 |
| 默认租户 | 确认 000000 存在且启用；不使用生产数据测试删除或状态切换 |
| 取证与清理 | 保存脱敏请求、响应、截图及前后数据；按关联关系清理本次创建的测试数据 |

涉及停用和删除的用例应各自准备独立数据，或执行后恢复状态，避免前一用例影响后续结果。不同测试人员并发执行时使用各自唯一编号。

## 功能测试用例

本页用例执行状态均为待执行。每条用例的实际结果及证据统一填写到执行记录。

### TC-TEN-001 管理入口和列表访问

关联 REQ-TEN-001；优先级 P0。前置：S 已登录，菜单已配置。

步骤：打开租户管理页面并刷新；直接调用列表接口。预期：页面正常展示，接口返回分页结构；列包含编号、名称、状态等，页面不显示导出入口。

### TC-TEN-002 组合筛选与分页

关联 REQ-TEN-002；优先级 P1。前置：准备至少 11 条租户数据，包含名称片段相同但编号和状态不同的记录。

步骤：依次按完整编号、名称片段、状态查询，再组合查询；清空条件，以每页 10 条切换分页。预期：编号精确匹配、名称模糊匹配、状态准确；组合条件同时生效；总数正确，按主键升序，翻页无重复或遗漏。

### TC-TEN-003 新增租户

关联 REQ-TEN-003；优先级 P0。前置：S 登录，测试编号未被使用。

步骤：新增合法编号、名称和备注，保持默认正常状态；提交后查询记录。预期：仅新增一条记录，列表刷新，后端生成主键；名称及编号的首尾空格被页面去除；再次打开新增表单时无旧数据残留。

### TC-TEN-004 编辑基本信息

关联 REQ-TEN-004；优先级 P0。前置：存在独立测试租户 A。

步骤：修改名称、备注并停用，保存后查询；再改回正常。预期：名称、备注和状态持久化；编号不可编辑且保持不变；列表刷新；保存中显示加载状态。

### TC-TEN-005 删除空租户

关联 REQ-TEN-006；优先级 P0。前置：独立租户 E 没有关联用户及业务数据。

步骤：点击单条删除，先取消，再确认删除；查询列表和详情。预期：取消时数据保留；确认后记录删除、列表更新；后续详情查询返回“租户不存在”。

### TC-TEN-006 超级管理员租户选项

关联 REQ-TEN-007；优先级 P1。前置：启用 A、B 和停用 C 同时存在。

步骤：使用 S 调用选项接口。预期：返回 A、B 及其他启用租户，不含 C；只选择规定的四个业务字段，按 id 升序排列。响应包装字段不属于此处的租户字段限制。

## 边界与校验用例

本页用例执行状态均为待执行。绕过页面的校验场景通过接口直接构造请求。

### TC-TEN-007 必填及状态校验

关联 REQ-TEN-003；优先级 P0。步骤：逐项省略或传空白 tenantId、tenantName；status 分别缺省、传空、传 2。

预期：请求被拒绝，数据库不新增记录；页面必填提示与接口校验均有效。普通新增页面默认状态为 0，不代表接口允许缺省状态。

### TC-TEN-008 编号字符及长度

关联 REQ-TEN-003；优先级 P1。步骤：使用互不重复的编号分别覆盖 1 位、20 位、21 位；合法组合包含字母、数字、下划线、短横线，非法组合包含中文、空格或斜杠。

预期：合法 1～20 位编号创建成功；超长和非法字符被拒绝；失败请求不落库。页面裁剪与接口拒绝须分别验证。

### TC-TEN-009 名称及备注边界

关联 REQ-TEN-003；优先级 P1。步骤：分别测试名称 100 字和 101 字、备注空值、500 字和 501 字；每次使用唯一编号，其余字段合法。

预期：名称 100 字、备注为空或 500 字可提交；名称 101 字或备注 501 字的接口请求被拒绝；前端限制输入长度。字符计数使用常用汉字或 ASCII，避免混入表情导致计数歧义。

### TC-TEN-010 重复与保留编号

关联 REQ-TEN-003；优先级 P0。步骤：先创建编号，再使用完全相同编号新增；另尝试 `__platform__`；最后用不同编号但相同名称新增。

预期：重复编号返回“租户编号已存在”，保留编号被拒绝，均不新增记录；名称相同、编号不同在当前规则下允许创建。大小写是否视为同一编号需结合数据库排序规则确认。

### TC-TEN-011 非法编辑请求

关联 REQ-TEN-004；优先级 P0。步骤：绕过页面修改已有租户的 tenantId；另构造无 id 的更新请求，以及 id 不存在的更新请求。

预期：三种请求均被拒绝，原记录不变；不允许通过编辑接口变更租户编号或意外新增记录。

### TC-TEN-012 默认租户保护

关联 REQ-TEN-005；优先级 P0。步骤：检查 000000 的页面状态控件、勾选框及删除操作；直接调用接口尝试停用和删除。

预期：页面不能修改状态、不能勾选且不显示删除按钮；后端拒绝停用与删除，默认租户仍存在且启用。

## 权限与联动用例

本页用例执行状态均为待执行。权限拒绝以响应体、业务结果及数据未改变共同判定。

### TC-TEN-013 关联数据保护

关联 REQ-TEN-006；优先级 P0。步骤：分别准备仅有关联用户、仅有关联业务数据的租户，以 S 调用删除。

预期：两类删除均被拒绝，提示“租户仍有关联用户或数据，请停用租户”；租户及关联数据完整保留。按当前 COUNT 逻辑，仍在表中的逻辑删除记录也可能阻止删除，需要业务确认策略。

### TC-TEN-014 批量删除原子性

关联 REQ-TEN-006；优先级 P0。步骤：批量删除无关联 E 和有关联 D，再颠倒顺序重试；另将 E 与默认租户组合删除；最后使用两个无关联租户批量删除。

预期：前三次整体失败，所有目标租户保留；最后一次全部成功，不出现部分删除。

### TC-TEN-015 普通用户绕过页面访问

关联 REQ-TEN-001；优先级 P0。步骤：UA 直接调用列表、详情、新增、编辑、删除五类管理接口，使用独立测试数据。

预期：均返回权限拒绝，“仅超级管理员可以管理租户”；查询不泄露租户信息，写操作不改变数据库。权限控制不能仅依靠菜单隐藏。

### TC-TEN-016 普通用户选项范围

关联 REQ-TEN-007；优先级 P0。步骤：UA、UB 分别调用选项接口；尝试附加另一个租户编号的请求参数。

预期：UA 只获得 A，UB 只获得 B；附加参数不能改变身份对应范围；停用租户不出现在选项中。

### TC-TEN-017 停用与恢复登录联动

关联 REQ-TEN-008；优先级 P0。步骤：保留 UA 已登录会话，由 S 停用 A；UA 使用旧会话请求业务接口，再尝试重新登录；恢复 A 后再次登录。

预期：停用后旧会话的受校验请求及新登录均被拒绝；恢复后可重新登录。此规则不等于主动销毁已有 Token，退出登录接口仍可按当前放行规则使用。

### TC-TEN-018 业务数据租户隔离

关联 REQ-TEN-008；优先级 P0。步骤：UA 查询用户等受租户隔离的数据；直接用 B 的记录主键尝试读取或修改；尝试在新增请求中伪造 tenantId 为 B。

预期：UA 不获得或修改 B 的业务数据；新增记录归属由可信登录上下文确定；共享平台表按配置处理，不适用该隔离断言。
