# 数据审计实施说明

本次实现采用两张表、两个只读视图，菜单位于「合规管理 → 数据审计」。本说明描述实际代码；同目录早期功能说明书是方案讨论资料，不作为本次全部功能已实现的依据。

## 使用方式

- **变更记录**：查看样本及非样本操作，按样本编号、分析数据 ID、对象范围、操作、操作人筛选；打开详情查看真实记录主键、变化字段及修改前后值。
- **样本履历**：输入完整 `subbarcode`，按服务端操作时间、事件 ID 从早到晚排列；可按 `analysis_id` 查看某份分析数据，并包含该样本公共信息和质控事件。
- `subbarcode` 按业务约定全局唯一；同一样本的不同数据批次以 `analysis_id` 区分，报告关联实际 `report_id`。审计功能不改变既有报告版本生成规则。
- 两个视图均只有查询功能，不提供审计新增、修改、删除或恢复业务数据的入口。普通用户只可查询所属药企；现有系统管理员按既有平台权限跨药企查询。

## 留痕机制

`audit_event` 保存操作者、时间、业务动作、药企及样本/分析/报告关联；`audit_change` 保存实际表、完整主键、变化类型、受控前后快照和字段差异。同一业务事务内合并多表变化，同一跨药企批次按真实药企及样本分别归属。

显式接入现有写入入口，在写入前读取持久化记录，在提交前读取最终值并写入审计；业务与审计共同提交或回滚。审计保存失败时业务操作失败。密码、Token 等凭证不进入快照，清空值保留为 `null`，技术更新时间不伪装成业务变化。质控同值重导保留 `NO_CHANGE` 事件。

当前接入：

| 范围 | 已接入的业务写入 |
| --- | --- |
| 样本 | 新增、编辑、删除、Excel 导入的逐行新增/更新 |
| 湿实验与生信质控 | 导入、编辑、删除，包括跨药企接收及同值重导 |
| 解读与状态流转 | 生信查看/复核完成、解读/审核领取、报出位点选择、解读结论、历史复用与报告历史固化、提交/通过/驳回 |
| 报告 | 生成轮次、版本序号与文件命名登记、生成结果、送签及签署状态、发送登记和结果 |
| 系统管理 | 用户及角色的新增/修改/删除、状态、用户角色关系、角色菜单关系、密码重置操作事实 |

外部扫描、文件重驱动调用记录发起与返回结果；扫描器直接写数据库的逐行位点导入、外部初次上传以及人工 SQL 不会自动形成完整前后快照。后续若要纳入这些写入，需要对接扫描器或统一写入口。本次不回填历史审计，不把 SMTP 接受发送等同于收件人已收件，不包含审计复核、电子签名合规验证或数据库防篡改存储建设。

## 上线顺序

1. 执行 `template-backend/script/sql/update/update_5.6.28-data-audit.sql`，创建两表并将菜单挂到现有合规管理目录；脚本可重复执行。
2. 发布包含 `ruoyi-audit` 的后端与本次前端构建；菜单默认授予现有管理员，其他角色按需要分配 `compliance:dataAudit:list` 与 `compliance:dataAudit:query`。
3. 从上线后新的业务操作开始产生记录。先迁移数据库，再启动新后端，避免业务写入因审计表缺失而回滚。

## 验证入口

后端隔离验收包：在 `template-backend` 下运行（避免覆盖正在运行的普通 JAR）：

```powershell
mvn -B -ntp -Paudit-verification -pl ruoyi-admin -am '-DskipTests=false' '-Dprofiles.active=local' '-Dtest=Audit*Test,*Revision*Test,Report*Test,Interpretation*Test,SampleFlowReviewClaimTest' '-Dsurefire.failIfNoSpecifiedTests=false' package
```

真实数据库/API 验收：`template-backend/script/tests/data_audit_regression.py`，使用随机隔离 MySQL 库和独立端口，结束自动清理；依赖本机 `bcrypt`、`requests` 及已有测试 MySQL/Redis 容器，可用环境变量选择 MySQL 容器、源库和端口。预期输出 `DATA_AUDIT_API: PASS`。启用 `AUDIT_TEST_UI=1` 并指定已有 Playwright 包路径后，追加 `DATA_AUDIT_UI: PASS`。

覆盖边界：跨药企列表/详情及签署回调拒绝、同一样本不同分析数据隔离、真实前后值、同值质控导入、审计写入失败共同回滚、无公开审计写删接口，以及浏览器查询/详情/离线失败重试/重置/空结果/窄屏。

本次验证：60 个后端测试全部通过；真实 MySQL/API 41 项断言通过，浏览器流程通过；前端 ESLint、Oxlint、类型检查及生产构建通过；可读性及页面结构闸门错误数为 0；隔离库 51 张表的数据库规范检查错误数为 0（2 项原有复合主键提示）。新增页面的严格 UI 静态审计为 0 问题；全项目审计仍有主题抽屉与全局滚动条的 2 项存量问题。可读性仍有 53 项提示，涉及已修改文件内的既有方法、合法空值返回、泛型等机械提示；未宣称提示已全部清零，独立只读评审结论为通过。

执行日志位于本地 `target/audit-tests-local.log`、`target/audit-api-ui-tests.log`、`target/audit-frontend-build.log` 及 `target/audit-*-schema.json` 等文件；不作为生产数据提交。测试中确认审计包装不改变签署回调的原租户访问范围。验收仅运行在隔离库与独立端口，未迁移或重启当前开发业务服务。
