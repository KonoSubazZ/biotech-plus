## 1 模块目标与范围

本模块用于人工登记 IQ（安装确认）、OQ（运行确认）、PQ（性能确认）的执行信息与结果，保存验证标题、版本、执行人、执行日期、结论摘要及一份关联附件。当前支持分页查询、新增、编辑和附件下载，不提供删除、导入、导出、审批或电子签名流程。

结果枚举为 passed（通过）、failed（未通过）、na（不适用）。它们是用户选择的记录值，不是后台自动执行测试后生成的判定。新增表单默认 IQ 和通过；执行人、日期、摘要和附件均可不填。记录显示“通过”不能作为本次业务用例通过、已完成 3Q 验证或系统符合某项监管要求的证明。

当前未建立 IQ → OQ → PQ 的前置校验，也未把记录与发布版本、开发记录或 3Q 文档的主键关联。version 为普通可选文字，executedBy 为手工录入文字；二者分别不代表已核验的发布版本、真实登录操作者。

本版未打开在线页面，页面描述来自 Vue 源码；未核实在线部署提交、角色授权、配置覆盖或历史数据。当前代码存在不代表已部署或已验收。本文仅覆盖 3Q 验证记录，其他合规菜单能力不计入本模块。

## 2 当前实现与历史资料差异

历史设计描述 uuid 主键、PG 字段类型、全量列表、统一保存及删除接口，权限为 read:ComplianceRecord、manage:ComplianceRecord。当前实现为 Java / Spring Boot、MyBatis-Plus、MySQL bigint 自增主键和 Vue / Naive UI；列表服务端分页，POST 新增、PUT 修改，另有详情、上传和下载接口，无删除接口。

当前权限为 compliance:validationRecord:list、query、add、edit。初始化 SQL 给角色 1 授权，不能据此认定历史设计中的湿实验、生信、解读、运营角色已经创建或具有权限。具体授权以部署数据库为准。

仓库数据库规范将 validation_record 归为 append-only、不设置 del_flag 的记录表；实际控制器提供 PUT，服务通过 updateById 修改原行。因此本文按“无删除入口、允许原行编辑”记录现状，不将其表述为不可修改或完整版本追踪。附件同名写入同一目录，记录 version 字段不控制附件版本。

历史设计按执行日期、创建时间排序；当前服务按 executedDate 倒序、id 倒序。SQL 为 result 设置 passed 默认值，但 HTTP 写入仍有 NotBlank 和枚举校验，不能借数据库默认值省略接口必填项。

## 3 字段与持久化定义

ValidationRecord 对应 validation_record，继承 BaseEntity。八个业务字段在表单、Bo、实体和 Vo 中对应；返回还包含 id、createTime。没有 del_flag，不配置逻辑删除字段。

| 字段或约束 | 当前实现 |
| --- | --- |
| id | bigint 自增主键；新增表单不传 id；编辑必须提供存在的记录 id |
| validation_type / validationType | varchar(20)，非空；只允许 IQ、OQ、PQ；前端必选，新增默认 IQ |
| title | varchar(200)，非空；后端 NotBlank、Size(max=200)，前端必填 |
| version | varchar(50)，可空，仅长度限制；无版本格式、版本存在性和唯一性校验 |
| executed_by / executedBy | varchar(80)，可空，手工录入文字；不绑定用户表或登录身份 |
| executed_date / executedDate | SQL date，可空；Bo 为 java.util.Date；表单提交 yyyy-MM-dd，Vo 明确按 yyyy-MM-dd 输出，实际输入解析需联调核验 |
| result | varchar(20)，非空，SQL 默认 passed；Bo 仅允许 passed、failed、na 且必填；表单新增默认 passed |
| summary | text，可空，多行文本；Bo 未声明长度上限，不等于数据库可无限存储 |
| file_name / fileName | varchar(255)，可空，仅保存文件名；Bo 最大长度 255；记录保存未校验文件存在、上传来源或所有者 |
| 公共字段 | create_by、create_time、update_by、update_time；由项目底座维护，Vo 含 createTime，不能替代逐次修改历史 |
| tenant_id | varchar(20)，非空，默认 000000；普通业务 SQL 由租户拦截器附加归属条件，平台管理员可绕过过滤 |
| 索引 | 主键 id；idx_tenant_id；idx_validation_record_type(tenant_id, validation_type)；idx_validation_record_date(tenant_id, executed_date) |
| 表级约束 | utf8mb4_general_ci；没有标题、版本或文件名唯一约束，没有枚举 CHECK，没有删除标志 |

Bo 的必填、长度与枚举约束均显式适用于 AddGroup、EditGroup。查询不使用写入校验组；查询时未知类型或结果按普通非空字符串参与等值条件，不能推断为必然触发枚举校验错误。

全局 MyBatis-Plus updateStrategy 为 NOT_NULL，实体未单独声明各字段的清空策略。更新传 null 可能不写入相应列；前端移除附件将 fileName 设为 null，保存后的关联是否清空需重点核验。空串与 null 分别测试。数据库实际结构、配置覆盖和序列化行为以运行环境为准。

## 4 接口与权限

路径不含前端代理前缀。普通响应为 R，分页响应为 TableDataInfo；下载直接输出文件流。本版不编造 HTTP 状态码或统一错误码。

| 方法与路径 | 权限及请求响应 |
| --- | --- |
| GET /compliance/validationRecord/list | compliance:validationRecord:list；title、validationType、executedBy、result、pageNum、pageSize；返回 rows、total |
| GET /compliance/validationRecord/{id} | compliance:validationRecord:query；主键非空；返回详情，不存在时抛业务异常 |
| POST /compliance/validationRecord | compliance:validationRecord:add；JSON 请求体、AddGroup；操作日志 INSERT、RepeatSubmit；返回操作结果 |
| PUT /compliance/validationRecord | compliance:validationRecord:edit；JSON 请求体、EditGroup；要求 id；操作日志 UPDATE、RepeatSubmit |
| POST /compliance/validationRecord/upload | compliance:validationRecord:add；multipart/form-data 的 file；返回 data.fileName；操作日志 INSERT，未配置本接口 RepeatSubmit |
| GET /compliance/validationRecord/download/{id} | compliance:validationRecord:query；先查询记录，再按 fileName 输出 application/octet-stream 文件流 |

上传复用 add，下载复用 query，无独立 upload、download 权限。只有 edit 的用户能够编辑文字但不因此具有上传权限。列表文件名按钮未根据 query 单独隐藏，用户可能看到按钮但下载请求被后端拒绝。

列表响应包含摘要等记录字段，因此缺少 query 不代表无法读取记录内容。编辑从当前列表行复制模型，打开时不重新调用详情接口；不能把 query 当作前端编辑的必需前置权限。

## 5 开发实现说明

以下八节说明当前已有代码的职责和流程，不是新增开发任务。

### DEV VAL 001 页面与分页查询

关联 REQ-VAL-001、002。index.vue 使用 useNaivePaginatedTable，默认第 1 页、每页 10 条。查询模块包含验证类型、标题、执行人、结果；title 和 executedBy 用 LIKE，validationType 和 result 用等值，组合条件为 AND。服务按 executedDate、id 倒序，没有版本或日期范围过滤实现。

列表列为跨页序号、验证类型、验证标题、版本、执行人、执行日期、结果、记录文档、创建时间和操作。摘要没有列表列，但包含在返回模型中，编辑可回显。序号按页码和页大小计算，不是记录 id。可空文字或日期采用空值判断显示短横线；空串与 null 的显示不必相同。

验证类型显示 IQ 安装确认、OQ 运行确认、PQ 性能确认；结果通过为成功色、未通过为错误色、不适用为中性标签。未知枚举使用默认样式及原值，不应被当作通过。工具栏无选择删除、导出功能。

### DEV VAL 002 表单与人工结果

关联 REQ-VAL-002、003、004。维护抽屉宽度 600、最大 90%，包含八个业务字段。新增默认 IQ、passed，其余为空值或空标题；类型、标题、结果必填。执行日期使用可清空日期控件，摘要为多行文本，前端未以结果不同联动必填摘要、附件或执行人。

打开编辑从列表行复制模型，附件列表按 fileName 回显 finished。保存成功关闭并刷新，失败保留输入。保存期间确认按钮 loading、取消按钮禁用，但抽屉仍为 closable，未见保存状态对关闭图标、遮罩或 Esc 的统一限制，实际交互留待验证。

### DEV VAL 003 保存、编辑及无删除

关联 REQ-VAL-003、005、006、013。insertByBo 和 updateByBo 使用数据库事务，经 Mapstruct 转换后调用 Mapper 写入，按影响行数判断结果。更新先确认 id 非空，再 queryById 检查存在；不存在时抛“验证记录不存在”业务异常。Mapper XML 没有自定义查询 SQL。

当前允许修改类型、结果和其他字段；没有 IQ、OQ、PQ 顺序校验、结果转移限制、版本冲突校验或标题查重。没有独立修改历史表及旧附件版本机制。RepeatSubmit 仅为请求防重复，不能据此宣称有业务唯一性或多人编辑冲突保护。无 DELETE 映射、删除服务或 remove 菜单权限。

### DEV VAL 004 权限与药企归属

关联 REQ-VAL-007、008。Controller 在六个接口分别设置 SaCheckPermission；页面通过 add、edit 控制新增、编辑入口。validation_record 不属于共享表白名单，普通用户记录查询和写入依赖租户插件；平台管理员跳过租户过滤，不能将其全量可见误判为普通用户也可跨药企。

executedBy 是业务录入文字，create_by、update_by 来自持久化底座；操作日志记录请求行为。三者含义不同，不以手填执行人证明实际执行身份，也不以日志注解证明已部署日志存储或具备字段级修订链。

### DEV VAL 005 上传处理

关联 REQ-VAL-009、010、011。上传服务拒绝空文件、空原始文件名；将反斜杠转换为斜杠后取最后一段并去两端空白，拒绝空名、点和双点，再创建目标目录并 transferTo 写入。返回清理后的文件名供表单保存。

前端最多显示一个附件；虽然传入 file-size=20，但未见显式文件大小校验函数和扩展名 accept 白名单，不能把这个属性直接写成已生效的 20 MB 业务限制。后端本模块也没有扩展名、MIME 或内容检查；公共 multipart 配置约束单文件 10 MB、请求 20 MB，实际值还受部署覆盖及代理限制影响。

文件上传与记录提交是两次独立请求。取消抽屉、记录提交失败或移除附件只影响表单，不删除已上传物理文件；上传也不受记录保存的数据库事务回滚控制。

### DEV VAL 006 附件目录与下载

关联 REQ-VAL-010、012。服务读取 compliance.validation-record.upload-dir，仓库默认目录为 /ruoyi/server/upload/compliance/validation-record。本模块所有药企和记录使用该目录，没有再按 tenant_id 或记录 id 分目录；它与其他合规模块配置目录不同。

同名上传写入同一路径，会替换原文件；多个记录引用同名时下载内容随文件变化。保存 fileName 仅受长度约束，未绑定上传批次、药企或记录，也未校验存在性。记录的租户过滤不能提供相同强度的物理附件隔离；具备对应权限的用户可能引用目录中的已存在文件名，跨药企同名也存在覆盖影响。

下载先按 id 查记录，要求有 fileName，再拼接目录并 normalize，检查仍位于目标目录内且为普通文件后写出。此检查限制路径越界，不证明文件归属。缺失记录、空附件名、文件不存在或路径越界走业务异常。前端调用名为 zip 的通用下载方法，不意味着服务生成了 ZIP 压缩包。

### DEV VAL 007 异常、重复提交与并发

关联 REQ-VAL-011、013。上传完成回调解析响应 JSON，以 code=200 时的 data.fileName 更新模型；异常响应显示消息。失败回调同样解析 JSON，未见解析失败兜底。实际非 JSON 错误页、网络失败提示和上传状态恢复需要联调。

表单 saving 与上传生命周期未统一锁定，关闭抽屉或切换记录后的迟到上传回调需验证。当前没有乐观锁版本字段；两人基于旧列表行编辑时可能覆盖已有字段变更。重复请求防护的时间窗口及身份维度由项目底座决定，不在本模块文档编造数值。

### DEV VAL 008 SQL、配置与实现落位

关联 REQ-VAL-006、014。compliance.sql 包含 validation_record 的 CREATE TABLE IF NOT EXISTS、合规目录下的 validation-records 菜单，以及 list、query、add、edit 权限和角色 1 授权。没有 delete 或 remove 权限定义。CREATE TABLE IF NOT EXISTS 不会自动修复已有表结构差异。

本次在 script/sql/update 的文件名中未找到 validation 或 compliance 对应的独立升级脚本；不据此宣称所有部署已完成建表或升级。接口在 ruoyi-compliance 模块；页面、API 与类型声明分层维护。业务日期、类型和结果均取人工输入，没有验证执行引擎、审批状态机或证据一致性校验。

## 8 详细测试用例

### TC VAL 001 分页与跨页序号

用例编号 TC-VAL-001；关联 REQ-VAL-001；优先级 P1；状态 待执行。

前置与数据：普通用户具有 list，本药企准备 12 条记录。

步骤：进入列表，检查默认每页 10 条；翻到第二页，再修改页大小并刷新。

预期：当前服务允许这些变更，仍为同一记录 id；不要求结果转换审批或前序验证，不生成本模块独立历史版本。将这种现状与业务是否认可分开记录。

### TC VAL 013 缺失及不存在的记录 id

### TC VAL 014 可选字段及附件清空

用例编号 TC-VAL-014；关联 REQ-VAL-005、REQ-VAL-011；优先级 P0；状态 待执行。

预期：界面移除只将 fileName 置 null，不删除物理文件；在 NOT_NULL 更新策略下，null 可能不更新原列。记录实测回显，不能仅根据提交成功宣称已清空；空串单独核对。

### TC VAL 015 无删除、导入及导出入口

### TC VAL 016 四权限与六接口

### TC VAL 017 普通用户记录药企隔离

### TC VAL 018 平台管理员与执行人文字

用例编号 TC-VAL-018；关联 REQ-VAL-008、REQ-VAL-014；优先级 P1；状态 待执行。

### TC VAL 019 正常上传及下载一致性

用例编号 TC-VAL-019；关联 REQ-VAL-009、REQ-VAL-012；优先级 P1；状态 待执行。

预期：记录绑定返回文件名，下载内容与上传相同；以文件流返回，不因前端方法名 zip 就变成压缩包。下载文件名和中文字符兼容性以实测为准。

### TC VAL 020 空文件与文件名清理

用例编号 TC-VAL-020；关联 REQ-VAL-009；优先级 P1；状态 待执行。

前置与数据：专用目录，准备零字节文件及原名为空、点、双点、带斜杠或反斜杠、首尾空格的请求。

步骤：逐组调用上传，比较返回文件名和专用目录内生成文件。

预期：空文件和清理后无效文件名被拒绝；有效原名只保留最后一段并去首尾空白。不得根据原始路径创建目录外文件；异常消息及框架提前拦截情况按实际记录。

### TC VAL 021 大小及类型边界

用例编号 TC-VAL-021；关联 REQ-VAL-009；优先级 P1；状态 待执行。

前置与数据：确认有效部署限制，仓库默认单文件 10 MB、请求 20 MB；准备边界附近及超过限制的无害合成文件、不同扩展名和 MIME。

步骤：经页面和直接请求上传，记录实际请求大小、响应及代理限制。

预期：有效 multipart 和代理限制生效；不能把 file-size=20 属性当作已验证的 20 MB 限制。本模块无类型白名单，实际准入由现有处理链决定，不预填“只允许 PDF”等规则。

### TC VAL 022 同名附件影响多条记录

用例编号 TC-VAL-022；关联 REQ-VAL-010；优先级 P0；状态 待执行。

前置与数据：独立测试目录，两条合成记录引用同一文件名，已有内容 A。

步骤：上传同名内容 B，从两条记录分别下载并比较哈希。

预期：同名写入替换目录文件，两条记录均可能取得 B；不保留可按记录 version 取回的 A 版本。将观察结果作为共享目录现状，不能宣称附件不可篡改。

### TC VAL 023 跨药企同名及手填文件名

用例编号 TC-VAL-023；关联 REQ-VAL-008、REQ-VAL-010；优先级 P0；状态 待执行。

步骤：A 上传文件，B 使用同名上传；另在 B 自有记录提交已知合成文件名，再从 B 自有记录下载。

预期：当前目录无药企分层，同名存在覆盖影响；保存未核验上传归属，B 自有记录可能引用已存在文件。记录隔离不等于文件隔离；禁止在此例枚举真实附件名。

### TC VAL 024 缺失文件及下载路径边界

用例编号 TC-VAL-024；关联 REQ-VAL-012；优先级 P0；状态 待执行。

步骤：分别通过记录 id 下载，仅使用专用测试目录内外的无害占位文件。

预期：空名、缺失文件、非普通文件和越界路径不返回文件内容，产生业务异常；路径边界检查不自动证明目录内文件属于该记录或药企。

### TC VAL 025 取消及保存失败后的上传文件

用例编号 TC-VAL-025；关联 REQ-VAL-011；优先级 P1；状态 待执行。

步骤：分别上传后取消、移除附件、触发记录保存失败；检查表单、记录和物理文件。

预期：这些动作没有服务器删除接口，已上传文件不随取消、移除或数据库事务自动清理；不得将表单列表为空等同于文件已删除。

### TC VAL 026 上传与保存关闭时序

用例编号 TC-VAL-026；关联 REQ-VAL-011、REQ-VAL-013；优先级 P1；状态 待执行。

预期：确认按钮 loading、取消禁用按实现生效；上传与 saving 未统一锁定，迟到回调可能影响当前模型。记录最终 fileName 与实际行为，若错绑或丢失列为缺陷，不预判时序用例通过。

### TC VAL 027 网络及非 JSON 异常

用例编号 TC-VAL-027；关联 REQ-VAL-011、REQ-VAL-013；优先级 P1；状态 待执行。

步骤：分别触发上传和保存失败，检查消息、控制台、表单内容及重试。

预期：正常业务错误按消息展示，保存失败保留输入；上传回调直接解析 JSON，非 JSON 异常可能未被兜底。记录实际错误与恢复能力，不能将静态代码分析写成异常测试通过。

### TC VAL 028 重复提交与多人编辑

用例编号 TC-VAL-028；关联 REQ-VAL-005、REQ-VAL-013；优先级 P0；状态 待执行。

预期：新增、修改受底座 RepeatSubmit 控制，上传未配置该注解；窗口外同标题不因本模块唯一性规则被拒绝。无乐观锁，旧模型可能覆盖新字段，实际覆盖顺序需记录。

### TC VAL 029 3Q 独立性及未通过、不适用

用例编号 TC-VAL-029；关联 REQ-VAL-002、REQ-VAL-003、REQ-VAL-014；优先级 P0；状态 待执行。

预期：当前代码不要求按 IQ、OQ、PQ 顺序，也不对 failed 或 na 强制填写原因；版本不做关联存在性检查。保存成功仅证明登记成功，不证明验证活动已执行或前序条件成立。

### TC VAL 030 表、菜单、配置与持久化核对

用例编号 TC-VAL-030；关联 REQ-VAL-006、REQ-VAL-014；优先级 P1；状态 待执行。

预期：实际表与配置差异有据可查；已有表不因 CREATE TABLE IF NOT EXISTS 自动升级；记录与附件持久性分别验证。INSERT/UPDATE 日志注解对应事件可核对，不由此推断存在字段历史或完整 3Q 审计链。
