# 项目管理 质控标准开发测试文档

质控标准按药企、产品、质控项目和类别维护合格上下限，供后续湿实验与生信质控判定使用。当前配置 CRUD 已存在，自动判定链尚未在本地实现；本稿先补配置正确性，再明确判定联调及历史结果保护的开发目标。

本文用于需求评审、开发拆分和测试验收。基于现有实现补齐可落地的开发内容；“代码基线”只表示静态核对，“开发目标”表示建议改造后的行为，均不代表已通过业务验收。

当前菜单路由 /project/qc-standard，接口 /qc/qcStandard，后端位于 ruoyi-qc。列表按产品、质控项目、类别和状态查询，类别为 wet_lab/bioinfo，状态为 active/inactive；范围显示 min ~ max，null 显示无穷边界。新增编辑读取启用产品选项，默认湿实验、启用状态。

QcRecordServiceImpl 当前只有记录 CRUD，QcRecordMapper.xml 明确将产品桥接判定留待未来实现。旧 spec.md 中的 sample_file 名称桥接、qc-judge-helper.ts 和 passed/failed/non_numeric/no_standard 为历史设计，不能当作本仓已运行能力。标准配置保存成功不代表质控结论已自动产生。

## 2 字段接口与数据关系

### 2 1 主要字段和约束

| 字段或关系 | 当前实现与目标差异 |
| --- | --- |
| id / tenant_id | id 为 bigint 自增，药企列在 DDL；实体继承 BaseEntity，超管绕过过滤时需明确写入归属。 |
| productId | 必选产品 ID；当前只检查 Bo 非空注解，Service 未核验产品存在、启用及同药企，DDL 未声明物理外键。 |

| minValue / maxValue | varchar(50) 可空，无数值及大小关系校验；页面甚至提示可写 <0.5。建议第一版仅接受纯数值闭区间，表达式另评审。 |
| unit | 最多 30 字符，可选；当前自由文本。目标为数值与单位独立，判定前核对单位，禁止隐式换算。 |
| status / remark | 状态 active/inactive，备注 500 字符；需修复分组校验并补状态枚举。 |
| 逻辑删除与唯一键 | del_flag 逻辑删除；唯一键不含 del_flag，删除后新建相同组合可能数据库冲突，恢复或禁复用策略待评审。 |
| 产品回显 | 当前页面产品名称映射、搜索选项、编辑选项均来自 activeList；停用产品可能回退显示裸 ID 或不能正常选择。 |

## 4 开发内容与实施顺序

所有开发任务当前均为“待评审、未开发”。P0 先处理药企归属、输入有效性及数据一致性，P1 完成交互和异常反馈，P2 为依赖其他模块的联调。路径简称：F 为 template-frontend/src；P 为 template-backend/ruoyi-modules/ruoyi-project/src/main；Q 为 template-backend/ruoyi-modules/ruoyi-qc/src/main。完整源码路径见第 8 节。

### DEV QCS 001 修复校验分组与数值规则

优先级 P0；关联 REQ-QCS-005、REQ-QCS-006、REQ-QCS-007。

现状依据：Q/java/org/dromara/qc/domain/bo/QcStandardBo.java 使用默认组约束，Controller 调用 AddGroup/EditGroup。上下限仅校验字符长度；抽屉提示下限可写 <0.5，尚无配套解释器。

开发内容：显式配置新增编辑约束及编辑 ID 必填，新增不允许自带主键。先按待评审的纯数值闭区间规则实现：空白归一为无边界、至少一边有效、BigDecimal 比较 min≤max，0 不当空；精度与最大位数和字段容量匹配。禁止 NaN、Infinity、单位拼接或未经定义的比较表达式。类别和状态严格枚举，单位与数值分列。同步前端提示和校验。

完成标准：直接 API 也拒绝非法数据；测试 10/20 闭区间、单侧界、0、相等上下限、反向范围及非数值，TC-QCS-009 至 012。

### DEV QCS 002 校验产品归属并补全历史展示

优先级 P0；关联 REQ-QCS-002、REQ-QCS-003、REQ-QCS-008。

现状依据：QcStandardServiceImpl 没有查询关联产品，页面 index.vue、search.vue 和 operate-drawer.vue 全部只取启用产品。超管绕过租户且实体未提供显式目标药企。

开发内容：服务层读取真实产品，检查存在、未删、药企一致和新关联可用状态；标准药企由受信产品及上下文共同确定，超管明确范围。新增选择只用启用产品，历史回显和查询需包含已引用停用产品；可通过详情 VO 返回产品名称编码和状态，复杂查询置 Q/resources/mapper/qc/QcStandardMapper.xml。清楚区分无产品与无选项权限。

完成标准：跨药企或不存在产品不能引用；停用产品历史显示可理解，直接新建关联被拒绝；超管写入不落默认药企，TC-QCS-003 至 006、015、016。

### DEV QCS 003 统一组合唯一和删除后处理

优先级 P0；关联 REQ-QCS-004、REQ-QCS-007、REQ-QCS-009。

现状依据：组合唯一有应用查询和数据库索引，但删除行仍占唯一键；查重依赖租户插件，超管与实际目标药企的范围需对齐。deleteByIds 不验证逐条存在，assertNotReferenced 是空方法。

开发内容：项目名去空白及大小写策略需与 MySQL 比较规则一致；查询明确目标药企，捕获并发冲突。软删重建建议先提供明确占用错误，恢复流程经评审后单独实现，禁止绕过唯一键复制。批量删除先校验所有 ID、药企及使用情况再事务删除；标准与产品删除的并发使用同一一致性机制。历史使用关系尚未建立时明确前置依赖，不伪造引用表。

完成标准：组合边界、并发、删除后重建均有可解释结果；混合批次无部分删除，未知 ID 不返回假成功。TC-QCS-007、008、013、014、017、018。

### DEV QCS 004 明确标准生效和历史快照

优先级 P0 与 P2 分阶段；关联 REQ-QCS-008、REQ-QCS-009、REQ-QCS-010。

现状依据：当前标准可直接改上下限和停用，未见判定使用记录或版本快照。qc_record 的现有 CRUD 尚未联接标准，不能据此实施真实“已使用”引用判断。

开发内容：P0 先定义并验收新关联与启停规则，保存审计摘要；P2 在判定模块落地时记录使用的标准 ID、阈值、单位、类别及生效依据快照，或评审版本模型。已使用标准禁删，修改影响未来判定，不静默重算历史；人工确认与自动判定独立。任何新增快照字段或表必须先给出契约与增量迁移，不把该模型写成现有结构。

完成标准：停用不抹历史，恢复启用符合产品状态；对已有判定改标准后历史结果保持可复核，删除被使用标准拒绝。TC-QCS-015 至 020；下游未就绪的用例标待联调。

### DEV QCS 005 落地判定关联契约和边界测试

优先级 P2；关联 REQ-QCS-005、REQ-QCS-010。

现状依据：旧 spec.md 通过 subbarcode→sample_file.product_name→product_config→qc_standard 判定，存在同名及改名歧义。现有 QcRecordServiceImpl 和 Mapper XML 未实现此链，也没有当前已验证的判定接口。

开发内容：先确认样本与产品的稳定 ID 关联及药企边界；建议避免仅凭产品名跨药企匹配。服务层基于启用产品与启用标准按产品、项目、类别精确匹配，用统一数值规则比较，批量读取避免逐条查询。passed/failed/non_numeric/no_standard 作为待确认结果契约；缺产品、缺标准、多候选和单位不符均不应默认为通过。接口及性能目标在联调评审时确定。

完成标准：纯测试范围 10–20：9.99 失败、10 和 20 通过、20.01 失败；无标准与非数字分别可识别。类别、药企及产品名冲突不串用标准，TC-QCS-019、020；不宣称现已自动判定。

### DEV QCS 006 完善权限和保存交互

优先级 P1；关联 REQ-QCS-001、REQ-QCS-011、REQ-QCS-012。

现状依据：页面已有操作按钮鉴权及 saving/finally；产品选项请求失败直接 return，可能继续显示旧选项。抽屉 closable，保存时只禁用取消按钮；编辑使用列表行，需覆盖数据过期。

开发内容：明确 qc:qcStandard:list/query/add/edit/remove 与 productConfig:list 依赖，按最小授权评审选项权限拆分。产品数据使用受控加载与错误状态，失败禁止误选旧产品；保存中控制关闭图标、遮罩和 Esc，成功重取当前有效列表，失败保留输入。修改可选边界为空需显式持久化，单独验证 ORM 的 null 更新语义。批量删除显示确认范围。

完成标准：查询、回显和按钮权限一致，失败可重试，关闭与重复点击不产生模糊结果；TC-QCS-001、002、013、021 至 024。

### 数据库与交付要求

现有业务表带 tenant_id、审计字段和 del_flag。先检查部署库及异常存量，再决定迁移。新增字段、索引或约束需在 template-backend/script/sql/update 提供增量迁移、回滚或恢复步骤；不要仅修改初始化建表文件。简单查询用 MyBatis-Plus，复杂跨表查询放所属 Mapper XML，值参数绑定且验证药企隔离。

新增测试优先覆盖服务层规则与真实请求校验，再在隔离 MySQL 环境验证唯一键、逻辑删除、事务和租户 SQL 改写。涉及标准判定或历史结果的改造需要保留旧数据，不能在页面刷新时无提示重算历史结论。

## 5 测试准备与验收用例

隔离环境准备启用药企 A、B，平台超级管理员 S，各药企有管理权限用户 A1/B1，以及仅有查询权限的 A0。准备产品 PA/PB、启用及停用产品、启用及停用标准，以及无引用、已引用两类记录。名称和编码以 DOC_TEST_ 标记，边界测试另构造指定长度。凭据由测试环境提供，不写入文档。

产品与基因联调需准备只读 nkb.ncbi_gene 测试数据，包含人类唯一符号、重复符号、其他物种及不存在符号；不依赖真实生产库当前行数。标准阈值示例仅用于软件测试，不代表生产实验判定标准。执行前记录应用版本、数据库结构、药企上下文与权限，备份自建数据；执行后仅清理本次创建的数据。

每条用例默认操作者拥有对应权限，越权用例除外。对直接请求记录脱敏参数、业务响应、数据库前后状态及日志；未实现的目标标为未实现或失败并关联任务。缺少下游模块时记录阻塞原因，不把接口能保存当作判定链已验收。

### TC QCS 001 组合筛选与类别

用例编号 TC-QCS-001；关联 REQ-QCS-001；优先级 P1；口径：基线。

前置与数据：PA 有 wet_lab/bioinfo 标准，另有 PB 标准和停用记录。

步骤：按产品、项目关键字、类别和状态组合查询并翻页。

预期：结果和 total 正确，只显示匹配类别，不把相同项目的不同类别合并。

### TC QCS 002 重置空态和边界展示

用例编号 TC-QCS-002；关联 REQ-QCS-001；优先级 P1；口径：基线及目标。

前置与数据：准备无下限、无上限、0 边界及空字符串存量。

步骤：查询不存在项目后重置，检查范围列。

预期：空态无残留；null 用无界表达，0 明确显示；空字符串规范化后不显示含糊的空范围。

### TC QCS 003 跨药企标准访问

### TC QCS 004 超管归属与伪造药企

### TC QCS 005 产品存在性与可用状态

## 7 待确认事项与实现差异

1. 数值规则建议采用十进制闭区间，单侧可空但双侧不可都空，允许 min=max；0 有效。<0.5 等表达式当前没有解释器，建议第一版拒绝并修改占位提示。精度、最大位数、负值是否可用按具体指标评审。

2. 单位建议按指标统一并在判定前核对，百分数值采用 0–100 还是 0–1 需明确；本文不设生产阈值，不隐式换算。

3. 产品和标准建议同药企；超管明确目标药企，新建仅选择启用产品。停用产品既有标准保留可读信息，标准变更是否允许修改 productId 需决定。

4. 已使用标准建议禁删、保留使用快照。当前引用检查为空，且判定使用契约未建立，不能仅补一个虚构表查询；应分阶段落地。

5. 自动判定、样本产品稳定关联、历史快照及版本模型属于 P2 联调，当前未实现。旧设计的 5,000 条内存过滤上限不能直接继承为本项目性能承诺。软删同组合恢复和阈值并发修改策略也需评审。
