## 1 目标与业务边界

样本信息提供报告业务使用的样本基础资料，包括患者、样本、订单与治疗信息。当前以样本编号 barcode 作为业务键，以数值 id 作为维护主键。质控记录使用 qc_record.subbarcode 引用该编号，样本删除逻辑已据此检查引用。

当前范围包括分页列表、六类筛选、列设置、四组录入、单条与批量删除、Excel 模板下载及导入。122 个业务字段均为字符串，不可因“年龄”“金额”“日期”等名称就假定已有数值或日期类型校验。

本模块不等同于报告生成、解读、审核或发送。历史报告流程文档来自其他技术栈，只作为业务背景；不将其中 /api/report 接口、报告状态或电子签署视为本模块已有能力。样本保存成功也不代表自动生成报告或自动完成质控判定。

建议角色分工为录单人员维护资料、质控及报告人员按权限查询、药企管理员分配本药企权限、平台管理员处理跨药企业务。实际权限由六个接口权限点控制，角色名称和授权组合仍需业务评审。

## 2 当前实现与数据约束

### 2.1 页面与交互

列表使用 useNaivePaginatedTable，初始每页 10 条，服务端按 id 降序。表格包含 122 个业务列、选择列与操作列，支持列设置及横向滚动；导出按钮关闭。新增、修改、删除、导入按钮分别受对应权限控制，不能据此替代服务端鉴权。

新增与编辑使用同一个抽屉。患者信息 33 项、样本信息 28 项、订单信息 34 项、治疗信息 27 项，共 122 项，均已存在输入绑定。编辑从当前列表行复制数据，没有在打开时重新调用详情接口，因此存在陈旧数据覆盖风险。前端只显式配置条码必填；长度、格式、冻结和引用保护不能依赖此表单保证。

提交失败保留抽屉和输入，保存中确认按钮显示加载、取消按钮禁用；抽屉仍配置 closable，未看到关闭图标、遮罩和 Esc 与 saving 联动的明确限制，须补充实际交互验证。关闭未保存内容的确认也属于待评审交互。

筛选条件为样本编号、姓名、客户、录单癌种、录单产品、委托日期。文本使用 LIKE；客户条件是 customer_name 或 custom_desc 命中，其余条件与客户条件组合为 AND。日期筛选针对 enter_date，只有起止值同时存在才生效，上界拼接“23:59:59”，底层仍按字符串比较。单边日期、逆序区间与非法格式未在该服务显式处理。

### 2.2 字段与存储

字段全集以 SampleInfo、SampleInfoBo、SampleInfoExcelRow、前端类型和 report.sql 为对应依据，不以旧设计文档的裁剪字段集替代。四组表单与 Excel 均覆盖 122 项，但显示标签和 Excel 表头不是同一命名体系。

| 字段或分组 | 当前定义及开发关注点 |
| --- | --- |
| id / barcode | id 为 bigint 自增；barcode 为 varchar(100)，DDL 允许 NULL。业务期望条码必填，必须补齐服务端校验与存量检查，不能只靠数据库唯一键 |
| tenant_id / del_flag | tenant_id 为 varchar(20)，默认值 000000；del_flag 为 char(1)，0 有效、1 删除；普通业务 SQL 由租户拦截器隔离 |
| 唯一键与排序规则 | uk_sample_file_barcode(tenant_id, barcode)，不含 del_flag；utf8mb4_general_ci。已删除记录仍占键，大小写等价和空格行为需统一条码口径后实测 |
| 患者信息 33 项 | 含 patientName、patientPhone、birthDay、cancerType、familyFirst 等；age 长度 50，patientName 长度 100，cancerType 长度 256；患者信息属于敏感业务资料 |
| 样本信息 28 项 | 含 barcode、sampleType、sampleTime、libraryName、sampleProductCode、block 等；block 只是字符串，未见据此禁止更新或导入的业务规则 |
| 订单信息 34 项 | 含 customDesc、customerName、enterDate、erpTestName、contractsNo、orderMoney 等；customDesc 长度 256，customerName 长度 100；金额和日期当前均按字符串保存 |
| 治疗信息 27 项 | 含 firstTreatment、secondTreatment、thirdTreatment 及治疗方法、用药、疗效等；部分 varchar、部分 text，不能统一按 100 字符截断 |
| 长文本和附件描述 | geneResult、geneType、sampleRemark、pathologyReport、otherAttachments 等为 text；附件字段目前是文本输入，不代表已实现文件上传、预览和授权下载 |
| 公共维护字段 | create_by、create_time、update_by、update_time 与逻辑删除字段由现有底座处理；不能将这些字段误作完整逐字段审计历史 |

样本编号、标本编号 specimenNo、文库编号 libraryName、患者编号 pcode、产品编码 sampleProductCode 含义不同，不能互相替代。erpTestName 是录单产品名称，不能直接当作产品配置的稳定外键。对接报告前需评审产品、客户和样本标识的映射规则。

### 2.3 接口与权限

下表路径不包含部署代理前缀。权限前缀统一为 report:sampleInfo。响应、错误处理沿用项目封装，不将业务错误码直接等同于 HTTP 状态码。

| 方法与路径 | 权限与现有行为 |
| --- | --- |
| GET /report/sampleInfo/list | report:sampleInfo:list；分页及筛选；返回 TableDataInfo，包含 rows 与 total |
| GET /report/sampleInfo/{id} | report:sampleInfo:query；返回 R 包装的详情；找不到记录抛业务异常 |
| POST /report/sampleInfo | report:sampleInfo:add；JSON 请求体；新增事务，操作日志及 RepeatSubmit；返回 `R<Void>` |
| PUT /report/sampleInfo | report:sampleInfo:edit；JSON 请求体且 id 必须存在；更新事务，操作日志及 RepeatSubmit |
| DELETE /report/sampleInfo/{ids} | report:sampleInfo:remove；逗号分隔 id；先逐条检查存在及质控引用，再整体逻辑删除，具有事务 |
| POST /report/sampleInfo/importData | report:sampleInfo:import；multipart/form-data 的 file；返回 total、inserted、updated、failed、errors；没有导入专用 RepeatSubmit 注解 |
| POST /report/sampleInfo/importTemplate | report:sampleInfo:import；返回只含表头的 XLSX 文件，与导入共用 ExcelRow 定义 |

list 与 query 是不同权限。列表已返回完整业务列，不能把取消 query 权限理解为隐藏患者信息。当前导入权限独立于 add/edit/remove，持有 import 可以触发新增、覆盖及恢复；这是已实现的授权组合，是否沿用需明确评审。

### 2.4 新增修改与删除流程

新增：接收请求 → 检查活动条码重复 → 检查含已删除记录的占用 → 转换实体 → 插入。手工保存未见条码 trim。修改：检查 id、确认记录存在 → 排除当前 id 查重 → 更新；未见引用条码变更限制、冻结限制或版本冲突检查。修改到被已删除记录占用的条码时，未复用新增分支的友好提示，可能由数据库唯一约束报错。

重要差异：控制器分别使用 AddGroup、EditGroup 校验；Bo 的 NotBlank、Size 没有指定这些组，且两个组未继承 Default。静态代码显示这些字段约束可能不被当前分组触发，必须通过直接请求验证并修复，不能写成“后端已完整校验必填和长度”。导入也没有调用这些 Bo 校验。

删除：逐条查询记录 → 根据 barcode 统计未删除 qc_record.subbarcode 引用 → 全部通过后批量逻辑删除。引用统计不区分湿实验或生信，也不区分质控结果；存在任一未删除引用即阻止删除。某条不存在或被引用时，在当前事务内整批停止。服务返回值未核对实际删除数量，并发删除或引用新增仍需测试。

当前删除保护只看到质控引用查询，没有报告引用检查。超级管理员可绕过租户拦截器，而引用查询只带条码，存在其他药企同码质控误阻断风险。不能将跨药企管理员的行为直接推断成普通药企行为。

### 2.5 Excel 导入流程

下载模板 → 按固定列序填写 → 上传并解析首个默认工作表 → 遍历解析后的数据行 → trim 条码 → 新增、更新或恢复 → 汇总逐行结果。解析使用 ExcelUtil 的同步列表方法，不采用带 Bean Validation 的监听器重载。

ExcelRow 的 index 为 0 至 121，对应表格第 1 至 122 列。第 1 列 AGE、第 2 列 BARCODE，第 10 列表头为 CUSTOMEDESC，对应 customDesc。读取按列序，不按表头文案定位：改表头不会自动调整映射，移动列可能把数据写错。当前没有模板版本及严格表头校验，不能宣称任意录单导出文件都可安全直接导入。

活动条码存在时按 id 更新；不存在时查询包含逻辑删除的数据；命中旧记录则先恢复 del_flag 再更新，计入 updated；完全不存在才插入。重复导入不是“跳过重复记录”，同文件同条码也会按行顺序处理。空单元格是否保留旧值受解析结果及 MyBatis-Plus 字段更新策略影响，应分别验证 null、空串和省略字段，不能把页面“覆盖”理解为保证全字段清空重写。

导入未设置整体事务，允许部分成功。恢复和后续更新也是两次独立写入，后者失败时前者可能已提交。insert/update 返回行数未检查，存在计数与实际写入不一致风险。建议保留行间部分成功，但使每一行完整原子提交，见 DEV SMP 004。

统计按输入数据行计数，不是唯一条码数；正常循环结束时 total 应等于 inserted + updated + failed。错误行号目前由解析列表下标加 2 推算，含空白行时是否对应原 Excel 行号需验证。异常明细拼接原始异常信息，可能暴露内部 SQL 或过多业务数据。

前端显示只允许 xls/xlsx、50MB，组件写有 file-size 属性，但不能据此确认 NUpload 实际执行了大小限制；服务层只显式检查空文件，部署上传上限仍需核实。前端结束回调统一提示导入成功，即使所有行失败；结果面板以 inserted + updated 是否大于 0 判断成功，存在提示不一致。非 JSON 响应直接 JSON.parse，也需补充异常处理。

## 4 开发任务与落地说明

以下任务均为计划开发，尚未在本次修改代码。优先级 P0 表示影响数据正确性或隔离，P1 表示重要体验与完整性。先完成口径评审，再按依赖顺序开发；不能因文档列出任务就宣称修复完成。

### DEV SMP 001 统一字段校验与空值语义

P0，关联 REQ-SMP-002、003。修改 SampleInfoBo 的分组约束或校验入口，使新增、修改都触发必填及长度校验；导入复用明确的字段校验流程。先规范化条码，再校验和查重，保留前导零，不擅自改变大小写。

核对 122 字段在表单、类型、Bo、实体、ExcelRow、Vo、DDL 的映射；日期、金额等继续按字符串兼容存量，新增规范必须先明确合法格式和历史异常处理。建议省略字段保持原值、明确清空操作才清空，禁止用文件空格猜测用户意图；最终规则待评审。完成标准是新增、编辑、导入的同一非法值均产生可读错误，且数据不发生部分修改。

### DEV SMP 002 固化药企归属与权限边界

P0，关联 REQ-SMP-004、005。普通用户依赖服务端身份确定药企，拒绝通过参数改变归属；超级管理员的列表、查重、导入、恢复和引用检查需带明确目标药企。目标药企选择方式为拟设计契约，当前样本表单没有该字段，不伪装成已有参数。

在既有租户拦截机制上落实上下文或显式受控条件，不对全局拦截器做无关改造。评审 import 是否继续包含新增、覆盖、恢复，若拆分权限需同时改菜单迁移、后端注解与前端展示。以两药企同条码数据证明无误更新、误恢复和误阻断，不能只测管理员账号。

### DEV SMP 003 补齐引用与资料更正规则

P0，关联 REQ-SMP-006、007、015。在 SampleInfoServiceImpl 的修改、删除和导入更新路径统一检查引用；建议被质控引用的条码不允许直接改名，普通资料更正另行判定是否影响已有报告。

报告引用目前没有本模块可用查询契约；先与报告模块确定稳定样本标识、资料版本或快照、可更正字段及撤销机制，再增加引用判断。block 值域、冻结权限和解冻方式均待评审，不能凭非空字符串一律冻结。完成标准是手工与导入不能绕过相同保护，并对被阻断的原因给出可读说明。

### DEV SMP 004 实现逐行事务与恢复控制

P0，关联 REQ-SMP-009、010、011。保留外层循环独立汇总，将单行查重、恢复、更新放入真正生效的事务边界，可采用现有 Spring 事务能力的显式事务模板；不要在同类私有方法上加注解后假定代理生效，也不要将整份文件改为一个事务。

每次写入检查影响行数，只有事务提交成功才增加 inserted 或 updated。恢复必须与新内容写入同成同败；恢复权限及引用保护复用统一规则。并发唯一键冲突映射为明确行级结果，失败不影响其他独立行。是否新增 restored 独立统计字段待接口评审，当前仍将恢复计入 updated。

### DEV SMP 005 加固模板与导入输入

P0，关联 REQ-SMP-008、009、012。在 SampleInfoExcelRow 与 importExcel 解析入口增加模板结构验证，明确 122 列顺序、表头、工作表选择及模板版本策略。导入写入前发现缺列、错序、重复表头或不兼容版本应终止；若需兼容旧模板，采用已批准映射，不猜列。

为文件扩展名、实际格式、容量、行数与解析时间设服务端限制，具体数值由部署容量评审，不把页面 50MB 视为已生效配置。同文件重复条码建议预检并提示用户，选择拒绝整批或逐行拒绝须确认；大编号要求文本单元格并验证前导零，不能承诺能恢复已被 Excel 舍入的数字。

### DEV SMP 006 修正导入反馈与异常处理

## 8 待评审事项与实现差异

1. 药企与权限：建议普通用户仅维护本药企，平台管理员写入明确选择药企；import 是否继续包括覆盖与恢复，以及是否拆分权限，待评审。样本归属不可由请求体任意改变。
2. 条码与引用：建议已引用条码不可直接改名，报告采用资料通过更正或版本追踪处理；block 的冻结含义、值域和解冻权限待业务确认。现有删除只检查质控引用。
3. 导入语义：空单元格保留还是清空、同文件重复条码、重复上传、已删除样本是否允许自动恢复均待确认；当前宽松导入行为不是业务批准依据。
4. 模板与限额：是否兼容历史录单导出、允许哪些表头和工作表、模板版本及容量上限待确认；固定列序易错必须优先处理。
5. 输入与并发：分组校验不一致、恢复事务缺口、影响行数未校验、陈旧行编辑及引用竞争属于当前静态发现，需复现和修复；未执行时不报告为测试已失败。
6. 字段含义：birthplace 等标签、不同癌种字段、附件文本、金额及日期格式需逐项业务定义；不得未经确认合并近似字段。数据与报告映射先定契约再实现。
7. 隐私与追踪：列表完整字段可见范围、脱敏方式及导入审计粒度待评审；当前操作日志注解不能证明已满足全部追踪要求。

以上补强方案均标为建议、待评审。本次仅提出样本信息模块规则，不将此前系统管理模块的确认自动扩展为本模块授权。
