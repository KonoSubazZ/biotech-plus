# 项目管理 产品配置开发测试文档

产品配置维护各药企可使用的检测产品及产品基因清单，为质控标准提供产品选项。开发重点是补齐药企归属与引用保护，确保导入的基因可核对、无静默遗漏，并保持产品停用、删除与下游配置一致。

本文用于需求评审、开发拆分和测试验收。基于现有实现补齐可落地的开发内容；“代码基线”只表示静态核对，“开发目标”表示建议改造后的行为，均不代表已通过业务验收。

菜单与接口已存在，不采用旧资料“尚无业务实现”的笼统结论。历史设计中的 React/Nest、UUID、/api 路径和 read:ProductConfig 等权限格式与本仓不同；当前为 Vue、Java、MySQL 自增 ID 及冒号三段权限。后续开发按已查证代码落位。

当前路由为 /project/product-config，已接入产品分页、启用产品列表、增改删及基因详情。主列表按名称、编码和状态筛选；服务端还支持检测类型等值筛选，但页面没有该输入项。产品表采用逻辑删除，同药企编码有唯一索引。

基因详情支持分页、符号搜索、计数和关系删除；添加有搜索选择、文本粘贴和 Excel 三种方式。符号查询限定 nkb.ncbi_gene 的 tax_id=9606，未匹配项不入库，有歧义时当前自动采用最小 gene_id 并提示。已有关系跳过，已软删关系恢复并计入 addedCount。

普通用户的业务表访问由药企拦截器过滤；超级管理员绕过该过滤。ProductConfig/ProductGene 请求及实体缺少明确目标药企字段，表又有默认 tenant_id，超管新增及向其他药企产品添加基因的归属需要补强。当前产品删除只检查有效质控标准，未见基因关系清理和数据周期策略检查。

## 2 字段接口与数据关系

### 2 1 主要字段和约束

| 字段或关系 | 当前实现与目标差异 |
| --- | --- |
| id / tenant_id | id 为 bigint 自增；数据库带 tenant_id，普通请求由上下文隔离。超管新增需明确目标药企，不能依赖默认 000000。 |
| name / code | 名称 120、编码 60 字符；Bo 有默认组必填与长度注解，但 Controller 使用 AddGroup/EditGroup，当前分组可能跳过这些约束。 |
| testType / relatedDiseases | 可选，设计长度分别为 60、500；页面为自由文本，无受控检测类型字典。 |
| reportCycleDays / status | 周期 Integer，前端未设最小值；建议补齐非负整数约束，并评审是否允许 0。状态应为 active/inactive，后端缺少枚举约束。 |
| remark / del_flag | 备注 500 字符，逻辑删除。唯一键 (tenant_id, code) 不包含 del_flag，删除后重建同编码可能冲突。 |
| product_gene | 产品与 gene_id 关系，冗余 gene_symbol 最长 24；唯一键为 tenant_id/product_id/gene_id。恢复软删关系已有专门 XML。 |
| genes / symbols | 搜索选择传 geneId+geneSymbol，当前服务直接采信；文本 symbols 去 BOM、首尾空白、空行和重复项，最多保留 20,000 个。 |
| 导入结果 | addedCount 含恢复，skippedCount 为已存在基因；unmatched 未入库，ambiguous 当前已选最小 ID 入库，不能相加当作互斥行数。 |

## 4 开发内容与实施顺序

所有开发任务当前均为“待评审、未开发”。P0 先处理药企归属、输入有效性及数据一致性，P1 完成交互和异常反馈，P2 为依赖其他模块的联调。路径简称：F 为 template-frontend/src；P 为 template-backend/ruoyi-modules/ruoyi-project/src/main；Q 为 template-backend/ruoyi-modules/ruoyi-qc/src/main。完整源码路径见第 8 节。

### DEV PRD 001 补齐产品与子关系药企归属

优先级 P0；关联 REQ-PRD-002、REQ-PRD-007、REQ-PRD-008。

现状依据：ProductConfig、ProductGene 继承 BaseEntity；TenantLineHandlerImpl 对超管跳过全部表过滤。ProductGeneServiceImpl 未核验目标产品存在、启用或归属，删除仅按关系 ID。

开发内容：在 P/java/org/dromara/project/domain 及 bo/vo 中按现有药企机制补齐可信归属。普通新增由上下文赋值，超管必须明确目标；基因关系从已校验产品继承药企，不能信任外部 tenantId。查询、计数、导入、恢复和删除都先校验产品及全部目标关系；XML 查询和恢复增加与目标药企一致的约束。前端展示所属药企，超管才提供选择。

完成标准：不存在、已删及跨药企产品无法新增关系；超管向 A 产品导入产生 A 的关系；混合非法 ID 整批拒绝。覆盖 TC-PRD-003、004、014、015。

### DEV PRD 002 修复请求校验与唯一性

优先级 P0；关联 REQ-PRD-003、REQ-PRD-004、REQ-PRD-005。

现状依据：ProductConfigBo 的约束未标分组，新增编辑却分别调用 AddGroup/EditGroup；两分组均不继承 Default。编码应用查重受超管绕过租户影响，可能比数据库的同药企唯一范围更大。

开发内容：在 Bo 中显式配置新增编辑校验，编辑 ID 必填、新增 ID 拒绝外部指定。校验状态、周期及长度，名称编码去首尾空白的规则前后端统一。唯一检查明确目标 tenant_id 并与数据库比较规则一致；将并发唯一冲突转业务提示。建议软删编码继续保留占用，若选择复用需单独迁移。空字段清除采用显式更新语义。

完成标准：绕过前端提交空值、越界和非法状态均拒绝；跨药企同码可建，同药企并发至多一条；编辑自身不误判，空值清除可回查。TC-PRD-005 至 010。

### DEV PRD 003 明确停用和删除的引用保护

优先级 P0；关联 REQ-PRD-006、REQ-PRD-007。

现状依据：ProductConfigMapper.xml 只统计 del_flag=0 的 qc_standard；ProductConfigServiceImpl.deleteByIds 未验证每个 ID 存在，并直接返回 TRUE；没有清理 product_gene。data_retention_policy 在该服务仍为未接入说明。

开发内容：停用只排除新选择，不自动删除标准或基因。删除先验证全部产品、药企和引用；有标准引用则整批拒绝。建议无下游引用时在同事务中逻辑删除产品及其自有基因关系，其他引用模块未就绪先明确范围。标准新增与产品删除之间需统一锁定或其他一致性措施，避免检查后并发产生孤儿。

完成标准：启用下拉、历史展示和新增关联规则一致；删除混合批次无部分成功，成功后无有效孤儿基因。TC-PRD-011 至 014。

### DEV PRD 004 验证基因来源并处理歧义

优先级 P0；关联 REQ-PRD-009、REQ-PRD-010。

现状依据：ProductGeneServiceImpl 当前直接采信 genes 的 ID 与符号；symbols 路径有歧义时自动选最小 ID。ProductGeneImportBo 没有嵌套 @Valid 校验或集合上限。

开发内容：所有入口到只读人类基因库核验 geneId 与规范符号，拒绝伪造、错误物种及过长符号。歧义符号仅列候选并由用户明确选择后再次提交；唯一命中项可继续处理。明确大小写、同义词支持范围，当前搜索只按主符号，不宣称已支持别名。规范化后按 geneId 去重，结果说明原始重复不计为“已有关系”。

完成标准：伪造 ID/符号不能入库，歧义项未确认前不关联；规范符号与真实 ID 可回查。TC-PRD-017 至 020。

### DEV PRD 005 完善导入限额与结果契约

优先级 P0；关联 REQ-PRD-010、REQ-PRD-011、REQ-PRD-012。

现状依据：normalizeSymbols 超过 20,000 直接 break，genes 路径未用同一上限。Excel 全量读取第一列并默认跳过首行；前端说明“可以有表头”会使无表头文件的第一条被漏读。

开发内容：统一三入口的候选总量、文件大小及行数限制；超限明确拒绝或提供可追踪分批，禁止静默截断。第一版建议必须有 gene_symbol 表头，明确错误提示；如要无表头导入须显式选择模式。返回新增、恢复、已有、未匹配、待确认及拒绝原因的可核对结果，系统写入异常整事务回滚；匹配失败为业务部分结果。并发同关系通过唯一键和恢复行数保证结果准确。

完成标准：20,000 与 20,001 边界行为可解释，无首行丢失；异常回滚后数据与统计一致，删除再导入恢复一条。TC-PRD-019 至 024。

### DEV PRD 006 修复详情计数与异步交互

优先级 P1；关联 REQ-PRD-001、REQ-PRD-008、REQ-PRD-014。

现状依据：product-gene-detail-drawer.vue 计数只在 visible 的非 immediate watch 中加载，而父组件 v-if 首次挂载已是 true，需验证首次打开计数是否仍为 0。基因搜索无请求序号控制；产品和标准抽屉 saving 仅禁用取消按钮，仍 closable。

开发内容：详情以产品 ID 为依赖统一初始化列表及计数，搜索结果数量与总基因数分别展示。快速查询忽略过期响应，切换产品清理选择和结果。保存、上传时控制关闭图标、遮罩与 Esc，失败恢复 loading 并保留输入；基因批量删除增加范围确认。列表删除最后一页回到有效页。

完成标准：首次打开已有基因产品计数正确；切换不串数据，重复点击、关闭及请求失败按规则反馈。TC-PRD-001、002、015、016、027、028。

### DEV PRD 007 校准权限配置与下游契约

优先级 P1；关联 REQ-PRD-006、REQ-PRD-013。

现状依据：产品菜单 project:productConfig:* 与基因 project:productGene:* 分离；质控产品下拉使用 productConfig:list。旧资料还提及样本名称桥接及数据周期策略，但当前对应集成未证实完成。

开发内容：给角色分别配置产品查看、维护和基因操作权限；仅会用产品下拉的角色如何最小授权先评审，再决定是否拆选项接口。记录改码改名对未来样本桥接的影响，优先以稳定产品 ID 关联；下游未实现时不添加虚假引用检查。审计保留目标产品、导入结果和操作者，文件及大基因列表不整段入日志。

完成标准：页面和直接 API 权限一致，缺选项权限有明确提示；产品停用历史可查，新关联受控。TC-PRD-011、012、025、026。

### 数据库与交付要求

现有业务表带 tenant_id、审计字段和 del_flag。先检查部署库及异常存量，再决定迁移。新增字段、索引或约束需在 template-backend/script/sql/update 提供增量迁移、回滚或恢复步骤；不要仅修改初始化建表文件。简单查询用 MyBatis-Plus，复杂跨表查询放所属 Mapper XML，值参数绑定且验证药企隔离。

新增测试优先覆盖服务层规则与真实请求校验，再在隔离 MySQL 环境验证唯一键、逻辑删除、事务和租户 SQL 改写。涉及标准判定或历史结果的改造需要保留旧数据，不能在页面刷新时无提示重算历史结论。

## 5 测试准备与验收用例

隔离环境准备启用药企 A、B，平台超级管理员 S，各药企有管理权限用户 A1/B1，以及仅有查询权限的 A0。准备产品 PA/PB、启用及停用产品、启用及停用标准，以及无引用、已引用两类记录。名称和编码以 DOC_TEST_ 标记，边界测试另构造指定长度。凭据由测试环境提供，不写入文档。

产品与基因联调需准备只读 nkb.ncbi_gene 测试数据，包含人类唯一符号、重复符号、其他物种及不存在符号；不依赖真实生产库当前行数。标准阈值示例仅用于软件测试，不代表生产实验判定标准。执行前记录应用版本、数据库结构、药企上下文与权限，备份自建数据；执行后仅清理本次创建的数据。

每条用例默认操作者拥有对应权限，越权用例除外。对直接请求记录脱敏参数、业务响应、数据库前后状态及日志；未实现的目标标为未实现或失败并关联任务。缺少下游模块时记录阻塞原因，不把接口能保存当作判定链已验收。

### TC PRD 003 跨药企产品和基因写入

用例编号 TC-PRD-003；关联 REQ-PRD-002；优先级 P0；口径：开发目标。
