# 系统管理 菜单管理开发测试文档

菜单管理维护系统目录、页面与按钮权限，并为角色授权及动态路由提供配置。开发重点是防止无效树结构、区分隐藏与停用的语义，并使菜单删除和权限收回对角色及在线用户正确生效。

本文件供需求评审、开发实施和测试验收使用。请先确认第 4 节的开发任务及第 7 节的业务决策，再按用例执行验收。当前代码存在对应模块，本次补充可实施的开发内容，不将代码存在等同于功能已验收。

## 2 当前实现与数据约束

当前页面采用目录树、节点编辑区及按钮列表。M 为目录、C 为菜单页面、F 为按钮；角色授权使用同一菜单数据。前端支持内部页面、外链与内嵌页，服务端生成动态路由，再由 F/store/modules/route/index.ts 转换。查询路由不等于授予接口权限，按钮权限由服务端权限标识校验。

菜单定义为平台共享配置。列表、详情及写入控制器检查 superadmin 角色和操作权限；非 GET 请求还受 userId=1 的共享配置拦截。树选择接口只检查 menu:query 并按身份返回可见菜单。隐藏控制导航展示，正常 M/C 才进入路由；但 SysMenuMapper.selectMenuPermsByUserId 的权限查询未筛选菜单 status，需要明确停用如何影响已有权限。

单节点删除要求没有子节点且未被角色使用；批量 cascade 删除要求提交集合包含全部子节点，并删除角色菜单关联。cascade 并不会自动替调用者递归补齐全部后代。父节点目前只禁止选择自身，未见祖先循环校验。

### 2 1 主要字段

| 字段 | 当前约束与开发关注点 |
| --- | --- |
| menuId / parentId | 菜单主键与父 ID；0 表示顶层父节点。前端树可能带虚拟根 0，它不应作为真实菜单保存。 |
| menuName / orderNum | 名称必填且最多 50 字符；同父节点重名检查；排序整数必填。 |
| menuType | M 目录、C 页面、F 按钮；Bo 仅非空，需补枚举及父子类型约束。 |
| path / component | 均最多 200 字符；服务端未统一按类型必填。内部页组件需与实际前端视图匹配。 |
| queryParam | 服务端校验 JSON 对象；内部参数由键值对生成，内嵌页使用 url 属性，需正确转义。 |
| isFrame / isCache | 前端使用 0 外链、1 内部、2 内嵌；Bo 注释仅 0/1，需统一契约。缓存 0 开启、1 关闭。 |
| visible / status | 0 显示或正常，1 隐藏或停用；两者意义不同，不可用隐藏替代权限撤销。 |
| perms / icon | 权限最多 100 字符，允许空或三段字母数字下划线标识，后二段还允许 *；图标支持本地及 Iconify 值。 |

以下为现有接口。路径参数用花括号表示；菜单列表返回统一响应中的数组，树及路由也不是分页列表。拒绝场景以业务响应与数据无变化为断言，不预设尚未运行确认的 HTTP 状态码。

| 方法与路径 | 用途及权限 |
| --- | --- |
| GET /system/menu/getRouters | 当前用户路由，依赖登录及身份，方法未声明 menu:list。 |
| GET /system/menu/list | 菜单列表，superadmin 角色及 system:menu:list。 |
| GET /system/menu/{menuId} | 详情，superadmin 角色及 system:menu:query。 |

## 4 开发内容与实施顺序

以下任务均为计划开发、待评审，尚未修改业务代码。P0 优先处理权限、数据正确性和事务问题；P1 补齐交互与异常。按任务顺序实施，接口或数据库方案评审通过后再编码。路径别名见第 8 节。

### DEV MENU 001 补齐树结构与类型校验

优先级 P0；关联 REQ-MENU-003、REQ-MENU-004。

现状依据：SysMenuController 只拦截 parentId 等于自身，SysMenuBo 缺少 parentId、menuType 枚举及条件必填；SysMenuServiceImpl 构树依赖合法层级。

开发方案：在服务层校验父节点存在且允许挂接，向上遍历祖先并设置已访问集合，拒绝循环；编辑类型时检查已有子节点兼容性。明确 M/C/F 字段白名单与条件必填，排除无关旧字段。统一 path 规范化后再执行同级名称、路径及路由名称冲突检查。

完成标准：孤儿、循环、按钮挂子、非法类型和冲突路径均在写入前拒绝；正常移动保留权限关系，TC-MENU-005 至 008 覆盖。

### DEV MENU 002 统一页面模式与参数序列化

优先级 P0；关联 REQ-MENU-005。

现状依据：前端菜单编辑支持 isFrame=2，而 Bo 注释只标 0/1；内嵌参数通过字符串拼接 JSON，内部参数解析缺少稳定容错。前端动态路由还会重算路由名。

开发方案：统一前后端三种模式枚举，内嵌页使用 JSON.stringify({url}) 生成参数；编辑非法存量 JSON 时提示修复，保留原始内容供定位。外链及内嵌校验允许协议，内部组件与实际视图注册表联调；检查路由名经 parseRouter 转换后仍唯一。空白布局限制按现有顶层菜单交互保留。

完成标准：含引号、中文和 & 的合法参数可往返；无效 JSON、非法协议或缺失组件明确拒绝或报告配置错误，无白屏，TC-MENU-009、010 覆盖。

### DEV MENU 003 统一停用与权限来源

优先级 P0；关联 REQ-MENU-006、REQ-MENU-007。

现状依据：SysMenuMapper.selectMenuTreeAll 筛选正常 M/C；selectMenuPermsByUserId 和 selectMenuPermsByRoleId 未直接筛选菜单状态。隐藏标记独立于权限。

开发方案：建议停用菜单或按钮从权限集合中排除；目录停用时子孙一并不可用，但不强行覆盖子节点原状态，以便恢复。将继承状态规则统一用于权限和路由查询，避免只改前端。按钮 perms 与对应控制器校验项逐项对照；空标识允许范围和通配符授予范围需评审。

完成标准：隐藏但正常的授权页面可直接访问；停用节点及被停用祖先覆盖的权限不可用，TC-MENU-011 至 014 覆盖。

### DEV MENU 004 加强删除集合与影响确认

优先级 P0；关联 REQ-MENU-008、REQ-MENU-009、REQ-MENU-011。

现状依据：单删拒绝角色引用，cascade 删除会清理角色关系且只验证提交集合包含子节点；前端树包含虚拟根 0。

开发方案：保留两种删除语义。批量请求先去重、排除或拒绝 0、检查所有 ID 存在并验证完整后代集合，再在单事务中删除菜单与角色关系。前端展示待删目录、页面、按钮数量及受影响角色，并要求确认；可复用已有查询或评审专用影响预览接口，不在本文宣称新接口已存在。

完成标准：不完整集合拒绝，完整集合只删指定子树；角色关联同步清理，模拟任一步失败整体回滚。TC-MENU-015 至 018、021 覆盖。

### DEV MENU 005 联动授权和在线路由刷新

优先级 P0；关联 REQ-MENU-010。

现状依据：菜单编辑和删除会改变角色授权来源，但菜单服务未见与角色服务同等的完整在线会话清理流程；前端路由与权限在登录状态中缓存。

开发方案：在删除前取得受影响角色及用户集合，事务后调用统一权限变更处理。停用、删除、修改 perms 时使旧权限失效；名称、排序等展示变化可提示刷新路由。清理失败保存可重试记录，避免失去删除前关联后无法定位用户。与用户和角色模块共享策略。

完成标准：权限撤回后旧会话 API 拒绝，新登录路由不含失效节点，无关用户可继续使用；TC-MENU-019、020 覆盖。

### DEV MENU 006 完善页面异常与配置回归

优先级 P1；关联 REQ-MENU-002、REQ-MENU-011、REQ-MENU-012。

现状依据：F/views/system/menu/index.vue 已对按钮列表使用请求中止控制；菜单树及编辑流程仍需覆盖加载失败、防重、选中节点删除和配置回显。

开发方案：树、详情、按钮列表分别维护错误及 loading，finally 释放；切换节点隔离旧响应，删除后选择有效父节点或清空。保存按钮防重，失败保留数据。为排序、图标、缓存、布局生成最小路由回归集；日志记录变更目标、字段摘要和结果，发布前导出测试配置备份。

完成标准：快速切换无串数据，错误可重试，页面刷新与授权树一致；TC-MENU-003、004、022 至 024 覆盖。

### 4 7 数据变更与联调要求

先沿用现有表和逻辑删除约定，不直接改初始化 SQL 充当已部署环境升级。若任务确需新增索引或字段，在 script/sql/update 下新增经评审的增量迁移；先检查存量异常，给出兼容及回滚方案。简单查询使用 MyBatis-Plus，复杂多表查询按项目约定放 Mapper XML。

每次改动同步前端 API 类型、参数绑定、服务端校验与测试。涉及数据库关系的写入在同一事务中完成；会话失效和缓存处理属于事务外效果，应在提交后执行并记录失败，不以数据库回滚假装撤销已失效的会话。

联调顺序：先补用户身份与药企归属校验，再处理角色及用户关系，最后联调菜单授权、路由与按钮权限。用户管理中的角色选择可先使用隔离环境预置角色，最终必须执行三模块联动验收。
