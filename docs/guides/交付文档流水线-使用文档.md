## 0. 一句话用法

流水线 = **隔离环境 + 种子数据 + playwright 采集（截图/接口原文/DB 核对）+ 生成器（md/docx/PDF）**。
脚本已随 skill 自包含，**不用回原工作目录翻文件**：

```bash
# 本机 shell
mkdir -p ~/project/qa/biotech-plus-v2
cp ~/.hermes/skills/software-development/module-design-and-test-doc-delivery/scripts/qa-pipeline/* ~/project/qa/biotech-plus-v2/
cd ~/project/qa/biotech-plus-v2
sed -i 's#qa/biotech-plus#qa/biotech-plus-v2#g' *.py *.sh   # 脚本里写死的是 v1 工作目录
```

两种典型任务：
- **重跑全量（v1 → v2）**：按第 3 章 9 步走。
- **新增一个模块**：按第 4 章复制模板改 4 处即可。

## 3. 重跑全量（v1 → v2）：9 步

> 记法：**【本机】** = 在你自己的 shell 执行；**【容器】** = 通过 `docker exec` 进容器执行。

### 步骤 1　起隔离环境【本机】
```bash
cd ~/project/qa/biotech-plus-v2
bash start_qa.sh start          # 起后端 8099 + 前端 9528；status 查看，stop 停止
```
检查点：输出 `QA 后端就绪 http://127.0.0.1:8099`、`QA 前端就绪 http://127.0.0.1:9528`。
目录约定：`$WORK/{files,reports,templates,logs}` 会被创建；模板放 `$WORK/templates/`。

### 步骤 2　同步菜单与权限【本机】
```bash
bash sync_qa_menu.sh
```
v2 新增的菜单/权限点必须同步到隔离库，否则页面进不去（表现为详情页空白、只剩“返回首页”）。

### 步骤 3　重算数据库结构快照【本机】
```bash
python3 dump_schema.py schema_<module>.json <表1> <表2> ...
# 例：python3 dump_schema.py schema_interpret.json analysis_report analysis_data analysis_file_status \
#        report_variant_history analysis_report_email_log sample_file report_template
```
**这一步不能省**：数据库设计说明书的表结构、字段、索引、DDL 全部来自它。

### 步骤 4　灌种子数据【容器】
```bash
docker exec -i biotech-plus-mysql mysql -uroot -proot --default-character-set=utf8mb4 ry_vue_qa \
  < seed_<module>_qa.sql
```
- 每个模块一份 `seed_*_qa.sql`；v2 表结构变了要同步改种子。
- 注意 `analysis_date` 等字段是 `varchar(8) 'YYYYMMDD'`，且解读列表**默认按“今天”过滤** → 种子的日期必须是环境当天。

### 步骤 5　采集截图【本机】
```bash
python3 capture_<module>.py list enter lims files variants preview review approve send extra operlog api scoped
```
- 不传 stage 就按默认顺序全跑；失败会落 `shots/zz_<前缀>_fail_<stage>.png` 并打印堆栈，**按 stage 单独重跑到通过**。
- 每个 stage 产出三类证据：界面截图、接口返回原文、数据库核对（`db_evidence`）。
- 采集脚本的坑（`set_content` 顶掉 SPA、stage 自导航、NSelect 虚拟列表、第二账号需父菜单授权）见
  skill 的 `references/qa-playwright-capture-pitfalls.md`，**改脚本前先读**。

### 步骤 6　生成三件套【本机】
```bash
python3 gen_docs_<module>.py
```
产物：`<repo>/docs/deliverables/<NN><模块名>/` 下 3 个 md + 3 个 docx，并自动转 PDF 到 `<WORK>/pdfcheck/`。
日志里应出现 `目录页码已收敛（第 N 遍），共 X 页`；未收敛说明目录/正文有变动，重跑即可。

### 步骤 7　缺陷汇总【本机】
```bash
python3 gen_defects_summary.py
```
产物：`00缺陷与待确认项汇总/`（缺陷条目 + 同源分组 + 待确认口径 + 部署注意 + 分批建议 + 各模块页数/结论行）。
注意：汇总文档**不引图**，跑完检查 `00…/截图/` 是否残留 `图00-页面迁移图.png`（有则删掉）。

### 步骤 8　SOP 指导书【本机】
```bash
python3 gen_docs_sop.py
```
产物：`11报告流转系统操作指导书/`（自动复用各模块已交付截图 + 新画一张报告流转流程图）。

### 步骤 9　自检（见第 6 章）并归档【本机】
```bash
cd ~/project/biotech-plus && git status --short docs/deliverables   # 应无输出（交付物不进库）
```

## 4. 新增一个模块怎么做

1. 复制最接近的两份脚本：
   ```bash
   cp gen_docs_bioinfo.py gen_docs_<新模块>.py
   cp capture_bioinfo.py capture_<新模块>.py
   ```
2. 改生成器顶部 4 处：`MODULE_NO` / `MODULE_NAME` / `OUT` / `FIG`（截图清单）。
3. 改采集器顶部：`PAGE_URL`（列表页路由）、`ADMIN/SCOPED` 账号、以及 `STAGES` 里的页签/按钮文案。
4. 写新模块的种子 SQL（`seed_<新模块>_qa.sql`）与正文三块（`DESIGN` / `TEST` / `db_blocks()`），
   然后按第 3 章步骤 3~6 跑一遍。
5. 最后把该模块补进 `gen_defects_summary.py` 的缺陷、待确认项与“各模块交付与验证结论”表。

## 5. 脚本清单与职责

| 脚本 | 作用 | 关键点 |
| --- | --- | --- |
| `docgen.py` | 文档引擎：封面（文档状态/保密级别/编号/签字栏）、变更履历、目录与页码回填、表格/图注/长表跨页 | 被各生成器 import |
| `gen_docs.py` | 最早一版模块生成器 + 通用能力（`E.build_pair` / `E.fig` / `E.prepare_figures` / `db_blocks` 样板）+ PDF 转换入口 | 其他生成器 `import gen_docs as E` |
| `gen_docs_<module>.py` | 单模块三件套生成器 | 顶部 `MODULE_NO/MODULE_NAME/OUT/FIG` |
| `gen_defects_summary.py` | 缺陷与待确认项汇总 | 汇总文档不引图 |
| `gen_docs_sop.py` | SOP 指导书（复用各模块截图 + 流程图） | 流程图用 `rankdir=TB`，别用 LR（字太小） |
| `capture_<module>.py` | playwright 采集：截图 + 接口原文 + DB 核对 | stages 可单跑；`db_evidence/api_evidence` 会顶掉 SPA（脚本内已处理自愈） |
| `dump_schema.py` | 从库导出表结构/索引/注释/行数 → `schema_*.json` | `python3 dump_schema.py <out.json> [表…]` |
| `seed_<module>_qa.sql` | 模块用例种子数据（隔离库） | 日期用 `YYYYMMDD` |
| `start_qa.sh` | 起/停/查隔离环境 | `start` / `stop` / `status`（默认 status） |
| `sync_qa_menu.sh` | 隔离库菜单与代码同步 | v2 加菜单/权限点后必跑 |
| `probe_*.py` | 单点探针（token、操作日志、字段校验） | 排查用 |

## 6. 交付前自检

**脚本自检（图号一致性）**
```python
import pathlib, re
d = pathlib.Path("docs/deliverables/<NN><模块名>")
files = {p.name for p in (d / "截图").glob("*.png")}
used = set()
for md in d.glob("*.md"):
    used |= set(files) & set(re.findall(r"图[\d\-]+-[^\n|()]*?\.png", md.read_text(encoding="utf-8")))
print("目录", len(files), "引用", len(used), "缺失", sorted(used - files), "孤儿", sorted(files - used))
```
期望：**缺失 无 / 孤儿 无**。

**人工自检**
- [ ] 长表跨页无“孤儿残片行”（用 125dpi 放大核对；docx 真身是整行，仅 OnlyOffice 的 PDF 可能出现残片）
- [ ] 封面签字栏、变更履历、目录页码齐备（生成日志有“目录页码已收敛”）
- [ ] 页面迁移图 / ER 图 / 流程图渲染正常、无乱码
- [ ] 交付物未进版本库；隔离库与正式库分离且**有证据**（正式库行数未变、正式服务未重启）

## 7. 常见故障排查

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 解读列表 0 条（等不到表格行） | 列表默认按“今天”过滤，种子的 `analysis_date` 不是环境当天 | 把种子的 `analysis_date` 改成环境当天的 `YYYYMMDD` |
| 详情页空白，只有“返回首页” | 账号角色的菜单未授到**父级菜单** | 给该角色补授父菜单（如「报告管理」），或重跑 `sync_qa_menu.sh` |
| `点「生成报告」报“模板文件不存在”` | 模板文件未按**模板名称.docx** 放到 `templates-root` 根目录 | 按报错里给出的文件名投放文件（与 `report_template.template_path` 无关） |
| `DOCX 渲染失败…JSON缺少模板顶层字段: xxx` | 模板文件实际含有的模块与模板声明的 `module_code` 不一致 | 换用模块自洽的模板；或挑“产品↔模板↔模板文件”三者齐备的组合 |
| 「发送报告」置灰 / 提示“没有可用的发件邮箱” | 邮件通道未配置（或样本缺性别/出生日期/报告接收人） | 配「报告管理 › 邮件配置」；补齐样本关键字段 |
| 采集卡在某个下拉/弹窗选不中 | NSelect 远程多选是虚拟列表，浮层拦截点击 | 不硬碰：记“自动化限制，建议人工复核”，或改用键盘/滚动定位 |
| `dot` 报语法错误、关系图生不出来 | `db_figure` 的 `pk` 没给全节点（生成空 `<FONT></FONT>`） | 给每个节点都在 `pk` 里指定主键字段 |
| 目录页码未收敛 / 页数跳变 | 正文或图片尺寸有变动 | 重跑生成器；页码会再迭代一遍 |
| `pdfcheck` 里没有 PDF | word2pdf / OnlyOffice 不可用 | 不影响 docx；目录页码会退回 Word 域，打开后按 F9 |
| 图片在 PDF 里出现残片行 | OnlyOffice 转 PDF 的已知现象 | 以 docx 为准；必要时放大核对而不是改文档 |

## 9. 铁律（不能越界）

1. **只写隔离环境**：库 `ry_vue_qa` + 后端 8099 + 前端 9528 + redis db1；收尾给出正式库/正式服务未动的证据。
2. **口径必须实测**：代码注释可能过期、口述可能与实现不一致 —— 以接口实现与实测结果为准，并在文档里写明证据。
3. **外部依赖不硬刚**：模板文件、邮件通道、外部网关不可用时先问；确认“按假定成功处理”就按假定继续，
   在测试报告里如实标注“假定 / 未执行 + 原因”，**不得伪造成功状态**。
4. **交付物不进版本库**，截图保留系统真实显示（含品牌与页脚版权行）。
5. **凭据留存复用**（隔离库口令、推送 token、账号），不要以安全为由删除既有凭据。
6. **采集脚本跟着构建走**：脚本里的表名/状态码是**当时那次构建**的口径，换构建后必须先对齐再重跑。
   2026-10-27 报告域已改为数字状态码（`report_status` 20~62，不再是 `PENDING_REVIEW`/`APPROVED`/`REJECTED` 字符串），
   `capture_interpretation.py` 已同步但**尚未在 QA 实跑**；重拍清单见
   `/home/liushangzhi/project/qa/biotech-plus/CAPTURE-RESHOT-TODO.md`。
